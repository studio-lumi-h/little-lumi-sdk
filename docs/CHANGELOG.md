# Little LUMI Model — 플러그인 API 변경 이력 / Plugin API changelog

플러그인이 기대도 되는 표면(`API.md`)이 앱 버전마다 어떻게 바뀌는지 여기에 적습니다 — 더한 것은 「추가」, 기본값만 돌려주는 빈 자리가 된 훅은 「폐기」. 실험 항목(「실험」 칩, `sdk.json` 의 `preview`)의 변경과 폐기도 여기에 적습니다.
Per app version: what changed in the surface a plugin may rely on (`API.md`) — "Added" for additions, "Deprecated" for a hook that became an empty default-only slot. Changes to and removals of preview items (the "preview" chip, `preview` in `sdk.json`) are listed here too.

## SDK 1.3.0 · 앱 1.3.0 · api_version 1 — 첫 공개 / First public release

- `API.md` 의 표면 전부가 이 버전에서 시작합니다 / The whole surface in `API.md` starts here.
- 버전 규칙: SDK 버전은 앱 버전과 같습니다(`sdk.json` 의 `sdk_version` = `app_version`); `api_version` 은 별개의 API 호환 번호이고 `PluginContext.API_VERSION` 도 `1` 입니다; 문서·예제만 바뀐 개정본은 버전을 유지하고 파일 이름과 `sdk.json` 의 소스 커밋(`commit`)으로 구분합니다 / Versioning: the SDK version is the app version (`sdk_version` = `app_version` in `sdk.json`); `api_version` is the separate compatibility number and `PluginContext.API_VERSION` is `1`; a documentation/example-only revision keeps the version and differs by the source commit (`commit`) in the file name and `sdk.json`.
- 안정·실험: 공개 표면은 안정과 실험으로 나뉩니다. 안정 항목은 같은 `api_version` 안에서 더해지기만 하고, 실험 항목은 `api_version` 을 올리지 않고 바뀌거나 없어질 수 있으며(이 파일에 적고 한 앱 버전 동안 빈 자리를 남깁니다) 앱 버전 하나를 바뀌지 않고 넘기면 안정으로 올립니다. 1.3.0 의 구분 기준: 자사 플러그인(LUMI Chat·Super Bongo)이나 앱 자체가 실제로 쓰는 문과 그 짝은 안정, 그 밖은 실험 — 목록은 `sdk.json` 의 `preview`, 규칙 전체는 `API.md` §8. 1.3.0 의 로더는 `api_version` 을 읽기만 하고 판단하지 않습니다 / Stable and preview: the public surface is split in two. Stable items only ever gain entries within one `api_version`; preview items may change or disappear without a bump (listed here, an empty slot kept for one app release) and are promoted to stable after surviving one app release unchanged. The 1.3.0 split: doors the first-party plugins (LUMI Chat, Super Bongo) or the app itself use, and their counterparts, are stable; the rest is preview — the list is `preview` in `sdk.json`, the full rules are `API.md` §8. The 1.3.0 loader reads `api_version` but does not act on it.
- 이벤트 26 토픽 — `ctx.on(topic, handler)`: `ready`·`behavior`·`bubble`·`choice`·`click`·`doubleclick`·`drag`·`throw`·`hover`·`mascot`·`headpat`·`affection`·`achievement`·`focus`·`alarm`·`pomodoro`·`bongo`·`settings`·`app`·`island`·`game`·`chat`·`tts`·`ask`·`settings_open`·`say_file`. 리스너는 플러그인마다 제 스레드(`lumi-plugin-events-<id>`)에서 돌고, `ctx.publish` 로 내는 토픽에는 `<id>.` 이 붙습니다 / 26 event topics — `ctx.on(topic, handler)`: the list above. Listeners run on a thread per plugin (`lumi-plugin-events-<id>`); topics a plugin publishes through `ctx.publish` are prefixed `<id>.`.
- 훅 15개 — `ctx.hook(id, (hook, current, ctx) -> …)`: `focus.quiet`·`focus.screen_busy`·`text.localized`·`sound.effect`·`behavior.force`·`bubble.duration`·`bubble.text`·`selftalk.line`·`selftalk.interval`·`speech.greeting`·`affection.award`·`affection.tier`·`place.allowed`·`bongo.key_frame`·`bongo.key_input`. 모드 탭 순서로 돌고 아래가 이기며 `null` 은 넘김입니다. 사용자가 건 약속(알람, 사용자가 누른 부탁, `say.txt`)은 훅으로 막을 수 없고, 앱이 스스로 고르는 것(혼잣말·인사)은 `""` 로 건너뛸 수 있습니다 / 15 hooks — `ctx.hook(id, (hook, current, ctx) -> …)`: the list above. Handlers run in Mods-list order, the lower one wins, `null` passes. Promises the user made (alarms, a request the user triggered, `say.txt`) cannot be cancelled through a hook; choices the app makes on its own (self-talk, greeting) may be skipped with `""`.
- `bongo.key_input`(안정): `frames`·`look` 을 받아 프레임 번호, 직접 입력 대기 `-1`, 코어 추정 사용 `-2`/`null` 을 돌려줍니다. 봉고가 화면에 있는 동안 입력 폴러가 40 ms 주기로 그 스레드에서 부르므로 기다리거나 I/O 를 하지 마세요. `bongo.key_frame` 도 함께 있습니다 / `bongo.key_input` (stable): given `frames` and `look`, returns a frame index, `-1` for provider idle, or `-2`/`null` for core inference. While the Bongo is on screen the input poller calls it every 40 ms on its own thread — handlers must not wait or perform I/O. `bongo.key_frame` is present too.
- `PluginContext` 의 문: 말하기·시키기(`say`·`sayTo`·`sayQueued`·`speak`·`behave`·`hideBubble`), 선택지(`ask`·`askFor`), 상태 조회(`mascots()` 등 위치·방향·행동, 호감도·집중 모드·언어·모니터), 캐릭터 제어(`summon`·`dismiss`·`moveTo`·`setCharactersVisible`·`awardAffection`(플러그인당 하루 상한)·`heart`·`playSound`), 자리(트레이 줄 `addTrayItem`/`addTrayToggle`, 정보 탭 단추 `addSettingsButton`, 캐릭터 메뉴 `addCharacterMenuItem`/`addCharacterMenuToggle`, 루미 탭 「기능 켜고 끄기」의 [적용] 시점 스위치 `addFeatureToggle`, `claimClickGreeting`), 전역 단축키(`bindHotkey`), 설정·문구·파일(`prefs()`·`text()`·`localized`·`setSetting`·`dataDir`·`writeAtomic`), 예약(`every`·`after`·`onEdt`·`offEdt`), 바이트코드(`onLoad`·`patch`, 그리고 앱이 실리기 전에 등록되는 `LumiTransformer` 서비스 — 보호 목록 `SteamGate`·`OfflineToken`·`Features`·`AffectionStore`·`Achievements`·`lumi.plugin.*`·`lumi.steam.*` 은 건네지지 않습니다) / The doors of `PluginContext`: speech and commands (`say`·`sayTo`·`sayQueued`·`speak`·`behave`·`hideBubble`), choices (`ask`·`askFor`), state queries (`mascots()` and the rest — position, facing, behaviour, affection, focus mode, language, monitors), character control (`summon`·`dismiss`·`moveTo`·`setCharactersVisible`·`awardAffection` (a daily cap per plugin)·`heart`·`playSound`), slots (tray rows `addTrayItem`/`addTrayToggle`, the Information-tab button `addSettingsButton`, character-menu rows `addCharacterMenuItem`/`addCharacterMenuToggle`, the Apply-time switch under Lumi → feature toggles `addFeatureToggle`, `claimClickGreeting`), system-wide hotkeys (`bindHotkey`), settings, strings and files (`prefs()`·`text()`·`localized`·`setSetting`·`dataDir`·`writeAtomic`), scheduling (`every`·`after`·`onEdt`·`offEdt`), bytecode (`onLoad`·`patch`, plus the `LumiTransformer` service registered before the app loads — the protected list `SteamGate`·`OfflineToken`·`Features`·`AffectionStore`·`Achievements`·`lumi.plugin.*`·`lumi.steam.*` is withheld).
- 생애: 플러그인은 의존 순서로 시작하고 실제 시작의 역순으로 멈춥니다. `start()` 가 던지면 그 플러그인의 `stop()` 을 즉시 부르고 컨텍스트로 건 것(리스너·훅·단축키·메뉴 줄·예약 작업)을 전부 거두며, 그 플러그인의 의존자는 시작하지 않습니다. 거둔 뒤의 컨텍스트는 죽은 것입니다 — 늦은 등록도 행동도 던지지 않고 무시되며 플러그인마다 한 줄 `<id>: registration after stop() ignored: <what>` 이 남습니다(읽기만 답합니다). `prefs().onChange` 리스너만은 컨텍스트가 거두지 않으므로 `stop()` 에서 직접 푸세요 / Lifecycle: plugins start in dependency order and stop in reverse start order. A `start()` that throws gets an immediate `stop()` and a full release of everything registered through its context (listeners, hooks, hotkeys, menu rows, scheduled tasks); its dependents do not start. After the release the context is dead — late registrations and actions are refused without throwing and logged once per plugin as `<id>: registration after stop() ignored: <what>` (pure reads still answer). A `prefs().onChange` listener is the one thing the context does not reclaim — release it yourself in `stop()`.
- 선언형 설정 카드: `plugin.json` `"settings"` — `bool`·`int`·`string`·`choice`·`hotkey`, 언어별 `label`/`hint`, 값은 `plugindata\<id>\settings.properties`(`ctx.prefs()`)에 바꾸는 즉시 저장, 기본값은 저장소에 없는 열쇠에만 심습니다 / Declarative settings card: `plugin.json` `"settings"` — `bool`·`int`·`string`·`choice`·`hotkey`, per-language `label`/`hint`, values saved at once to `plugindata\<id>\settings.properties` (`ctx.prefs()`), defaults seeded only for keys the store lacks.
- 데이터 조각(자바 없는 모드): `img\<Set>\conf\actions.d\*.xml`·`behaviors.d\*.xml`, `conf\language.d\<이름>_<locale>.properties`, `conf\self_talk.d\`·`conf\meet_dialogues.d\<이름>_<lang>.txt` — 켜진 모드 폴더에서 모드 탭 순서로 메모리 안에서 합쳐지고 아래가 이깁니다. `mod.json` `{"name","version","app_version"}` 은 모드 탭 칩이 됩니다 / Data fragments (mods without Java): `img\<Set>\conf\actions.d\*.xml`·`behaviors.d\*.xml`, `conf\language.d\<name>_<locale>.properties`, `conf\self_talk.d\`·`conf\meet_dialogues.d\<name>_<lang>.txt` — merged in memory from the enabled mod folders in Mods-list order, the lower one wins. A `mod.json` `{"name","version","app_version"}` becomes Mods-tab chips.
- 테스트 킷 `PluginTestKit`(`lib\Shimeji-ee.jar` 안): 기록하는 컨텍스트와 가짜 읽기, `publish`(동기)·`ask`·`tick`·`calls`·`lastCall`; 플러그인 생성·`ready`·`stop()` 은 검사가 직접 합니다. `tools\run_tests.py` 가 `test\*.java` 를 굽고 각각 제 JVM 에서 돌립니다(`-ea` 없음) / Test kit `PluginTestKit` (inside `lib\Shimeji-ee.jar`): a recording context with fake readings, `publish` (synchronous)·`ask`·`tick`·`calls`·`lastCall`; instantiating the plugin, `ready` and `stop()` are the test's job. `tools\run_tests.py` builds and runs `test\*.java`, one JVM each (no `-ea`).
- `plugin.json`: 필수는 `id` 뿐(`[a-z0-9][a-z0-9._-]{0,63}`)이고 `name` 이 없거나 비면 id 로 표시됩니다; `dependencies` 는 플러그인 id 의존(없거나 꺼져 있으면 시작하지 않음); 같은 id 를 두 jar 가 주장하면 모드 탭 아래 것이 실립니다; `hooks` 에 적은 모르는 id 는 로그와 칩으로 알릴 뿐 막지 않습니다; `app_version` 이 실행 중인 앱과 다르면 「N용」 칩(안내일 뿐) / `plugin.json`: only `id` is required (`[a-z0-9][a-z0-9._-]{0,63}`); a missing or blank `name` shows the id; `dependencies` are plugin-id dependencies (absent or disabled = this plugin does not start); when two jars claim one id the lower Mods-tab entry loads; unknown ids in `hooks` are logged and shown as a chip, never blocked; an `app_version` that differs from the running app shows an informational chip.
- 모드 탭 표시 규칙: 문자열은 글자 그대로 보입니다(HTML 은 해석하지 않습니다); 이름·작성자·버전·설정 라벨·선택지는 50자, 칩은 50자, 힌트는 300자, 상태·문제 메시지는 500자에서 잘리고 전문은 툴팁에 있습니다; 창작마당 항목 제목은 사용자의 UI 언어로 받아 옵니다 / Mods-tab display rules: strings are shown literally (HTML is never interpreted); name, author, version, settings labels and options are clipped at 50 characters, chips at 50, hints at 300, status/problem messages at 500, with the full text in a tooltip; Workshop item titles are fetched in the user's UI language.
- 창작마당: 구독을 끊은 플러그인 모드는 다음 실행에서 폴더째 사라집니다 — 동기화가 플러그인을 싣기 전에 돕니다; 앱이 켜진 채 끊으면 그 사본은 `DISABLED` 로 잠들고 다음 실행에 지워집니다. 끄기는 지우지 않습니다 / Workshop: a plugin mod unsubscribed on the Workshop is gone on the next launch — the sync runs before plugins load; unsubscribed while running, it is put to sleep (`DISABLED`) and removed on the next launch. Switching a mod off never deletes it.
