창작마당 제작자 데이터

WorkshopContent.promptSources(imageSet)는 모드 순서대로 정렬한 변경 불가능한 PromptSource 목록을 반환합니다(아래 모드가 충돌 시 우선). 각 레코드는 promptsFile()·personaFile()(Path, 읽기 전용이며 없을 수 있음), workshopId(), subscriptionId(), modStyleName()(Workshop ID가 포함된 페르소나 표시 이름 유지)을 제공합니다. 파일이 없거나 읽을 수 없는 경우를 처리하세요. 비활성·구독 해지·미승인 공급자는 제외하며 시작 후에는 준비된 목록만 제공합니다. 잘못된 캐릭터 이름이나 Workshop 미지원 구성에는 빈 목록을 반환합니다.

사용자가 명시적으로 선택한 제작자 프리셋을 두 식별자에 묶으세요. 업데이트·OFF/ON·일시적인 다운로드 대기는 구독 식별자를 유지하며, 구독 해지 후 재구독은 식별자가 바뀌어 새 선택이 필요합니다. 조회는 프롬프트 선택이나 코드 실행 동의가 아닙니다. WorkshopContent.hasDirectSource(id)는 구독 해지 기록까지 포함해 이전 사본의 중복 조회를 막는 용도이며 활성·승인 여부를 뜻하지 않습니다. 두 메서드는 컨텍스트 없이 본체 상태를 조회합니다.

2. 생명주기

모드에 실행 코드와 데이터를 함께 넣을 수 있습니다. 동의는 출처와 실행 파일의 목록·내용을 기준으로 하며, 이미지·음성 등 일반 데이터만 바뀌면 재동의를 요구하지 않습니다. plugins/runtime/의 동반 파일은 모두 실행 입력으로 검사합니다. Windows에서는 실행 파일 내용을 복사하지 않고, 하드링크와 쓰기·삭제 방지 핸들로 보호한 별도 실행 경로를 사용합니다. 일반 데이터는 원본에서 읽고 실제 사용 시 검증합니다. 비활성·미승인 코드 패키지는 데이터도 적용하지 않습니다. 모드 파일은 앱 종료 후 변경하세요.

Windows x64 DLL은 모드 루트의 native/ 또는 audio-native/에 둘 수 있습니다. 보조 인터프리터·실행 도구는 plugins/runtime/에 동반 파일과 함께 넣습니다. 이 디렉터리 전체는 실행 코드 묶음이며 EXE·DLL·PYD의 PE 형식을 검사합니다. 검증된 실행 경로에서 상대 폴더 구성을 유지하고, 클래스패스 JAR 옆에도 native/·audio-native/·runtime/ 경로를 보존합니다. 앱이 이 도구를 자동 실행하지는 않습니다. 코드 변경은 다시 동의를 받아야 하며, 설치 원본 경로나 원본 JAR 이름이 실행 경로라고 가정하지 마세요.

  • start(ctx) — 내장 기능이 뜬 뒤, 엔진(마스코트)이 실리기 전에 한 번 불립니다. 여기서 on/hook/addTrayItem/onLoad 를 겁니다. 이때 캐릭터 상태는 비어 있을 수 있으니 엔진이 필요한 일은 ready 에서 하세요. 던지면 그 플러그인만 실패로 표시됩니다.
  • ready 이벤트 — 엔진이 뜨고 모든 플러그인의 start 가 끝난 뒤 한 번, 앱이 냅니다. PluginTestKit 은 대신 내 주지 않습니다(§10).
  • stop() — 앱 종료 때 불립니다(기본 구현은 빈 것). start() 가 던진 경우에도 부분 시작을 정리하려고 곧바로 불리므로, 아직 초기화하지 못한 필드가 있어도 견디게 작성하세요. 플러그인과 한 jar 안의 서비스 구현들은 실제 시작의 역순으로 멈춥니다.
  • stop() 뒤 앱이 거둡니다: 이 컨텍스트로 건 리스너·훅·전역 단축키·메뉴 줄·기능 스위치·예약 작업은 플러그인이 정리하지 않았어도 로더가 전부 해제합니다. 시작 실패 때도 곧바로 해제하며, 실패한 플러그인의 의존자는 시작하지 않습니다. 실행 중 켜기·끄기는 없습니다(모드 탭의 스위치는 다음 실행부터).
  • 직접 만든 것은 직접 닫습니다: 창·클라이언트·스트림·작업 스레드는 stop() 에서 닫으세요. prefs().onChange(...) 리스너도 컨텍스트가 거두지 않습니다 — 등록 장부에 없으니 리스너를 들고 있다가 stop() 에서 removeOnChange(listener) 로 푸세요(§13 QuietPlugin). 이미 변환한 클래스는 되돌리지 않습니다.
  • 바꾼 상태도 되돌립니다: claimClickGreeting() 의 점유는 이 플러그인이 아직 쥔 경우에만 풀리고, summon() 으로 부르고 아직 dismiss() 하지 않은 캐릭터는 보내며, setCharactersVisible(false) 로 숨겨 둔 채였으면 다시 보입니다. 뒤의 둘은 앱이 계속 도는 동안(시작 실패)에만 하고, 앱 종료 때는 캐릭터에 손대지 않습니다.
  • 그 뒤로 컨텍스트는 죽은 것입니다: 늦게 오는 등록(on·hook·every·after·onEdt·offEdt·메뉴 줄·addSettingsButton·addFeatureToggle·bindHotkey·claimClickGreeting·onLoad·patch·ask·summon·dismiss·moveTo·setCharactersVisible)과 행동 문 전부(say·sayQueued·showBusy·behave·speak·mouthFlap·heart·playSound·awardAffection·publish·setSetting·writeAtomic·manageWindow)는 던지지 않고 무시됩니다 — 로그에 플러그인마다 한 줄 <id>: registration after stop() ignored: <what> 이 남고, 돌아오는 것은 무해한 값입니다(이미 취소된 ScheduledHandle, removed() 가 참인 MenuHandle/FeatureToggle, HotkeyResult.REFUSED, summon 은 -1, dismiss/moveTo/onLoad/patch 는 false). ask 의 콜백에는 -2 가 가는데, 이때만은 정상 경로의 전용 스레드가 아니라 부른 스레드에서 그 자리에서 전달됩니다. mascots()·prefs()·text() 같은 읽기는 계속 답합니다. 예외: beginMicCapture()는 종료된 컨텍스트에서 IllegalStateException을 던집니다. every()/after() 는 task == null(그리고 every 의 periodMs <= 0)을 해제 여부보다 먼저 검사하므로 죽은 컨텍스트에서도 IllegalArgumentException 을 던집니다. stop() 안에서 제 스레드를 멈추면 이 줄을 볼 일이 없습니다.
  • 같은 id 가 둘이면 모드 목록의 아래 것이 실리고 위 것은 DUPLICATE 로 표시됩니다. dependencies 는 시작 순서일 뿐 라이브러리 격리가 아닙니다.
  • plugins\lib\*.jar(앱 것 + 켜진 모드 것)는 클래스패스에 오릅니다 — fat jar 는 필요 없습니다. 코어 jar 가 항상 앞이라 코어 클래스는 가릴 수 없습니다.

3.12 플러그인 지형 · 실험

API동작
registerTerrain(name, List<TerrainRect>) → TerrainHandle · 실험이 플러그인의 바탕화면 지형을 등록합니다. 플러그인이 다르면 같은 이름을 쓸 수 있습니다. 같은 플러그인의 등록 중인 이름을 다시 쓰면 IllegalArgumentException입니다.
TerrainRect(id, left, top, right, bottom) · 실험바탕화면 논리 좌표의 사각형입니다. MascotState.anchor() 및 Swing 화면 좌표와 같은 공간이며 음수 좌표도 허용합니다. 너비·높이가 아니라 네 변의 좌표를 받습니다.
TerrainHandle.update(rects) → boolean · 실험해당 등록의 지형 전체를 교체합니다. 빈 목록은 모든 조각을 지우고 등록 이름을 유지합니다. 해제 후에는 false입니다.
TerrainHandle.remove(), close(), isRemoved() · 실험등록을 해제합니다. 중복 해제는 안전하며 이름을 다시 등록할 수 있습니다. 옛 핸들은 새 등록을 바꾸지 못합니다.
java
TerrainHandle platform = ctx.registerTerrain("platform", List.of(
    new TerrainRect("bar", 100, 400, 500, 408)
));
platform.update(List.of(new TerrainRect("bar", 100, 420, 450, 428)));
platform.update(List.of()); // 조각만 지웁니다.
platform.remove();          // 이름까지 해제합니다.

등록 이름과 조각 ID는 공백뿐인 값을 제외한 1~128자입니다. 한 등록 안의 조각 ID는 중복될 수 없고 최대 조각 수는 TerrainRect.MAX_PIECES(2048)입니다. right > left, bottom > top이어야 하며 너비·높이는 양의 int 범위여야 합니다. 잘못된 값은 이전 지형을 바꾸기 전에 예외를 발생시킵니다. 목록과 조각은 사본으로 전달하므로 호출 후 입력 목록을 수정해도 반영되지 않습니다.

모든 호출은 어느 스레드에서나 가능합니다. 엔진은 꼬미의 다음 이동 틱 전에 최신 목록을 반영합니다. 반환 성공은 데이터 접수를 뜻하며 착지 완료를 뜻하지 않습니다. 같은 틱 전에 여러 번 갱신하면 마지막 목록을 사용합니다. 조각 ID를 유지하면 기존 바닥 참조를 유지하고, 목록에서 빠진 조각은 바닥 참조도 무효화합니다. 이동하는 발판에 꼬미를 실어 나르는 기능은 제공하지 않습니다. 플러그인 종료·시작 실패 후 컨텍스트가 남은 등록을 자동 해제하며, 종료 후 등록은 이미 해제된 핸들을 반환합니다.

정원·미니게임·다른 플러그인의 지형은 각각 유지됩니다. 후보 순서는 미니게임 → 정원 → 플러그인 → 일반 창입니다. 플러그인 사이의 겹침은 등록 순서, 한 등록 안의 겹침은 조각 목록 순서로 먼저 나온 후보가 우선합니다. 화면과 바닥의 기존 엔진 규칙은 계속 적용됩니다. 현재 엔진은 작업 영역 상단에서 140 논리 픽셀 이상의 여유가 있는 사각형 윗변을 바닥으로 사용합니다.

이 API는 사각형 테두리를 창 지형처럼 제공합니다. 윗변 착지·걷기·발판 끝에서 지지면 상실은 기존 행동이 처리합니다. 그림의 불투명 영역 추출, 몸 전체의 장애물 충돌, 곡선 오르막 보정, 목표 점프, 접촉·파기 이벤트는 제공하지 않습니다. 바탕화면 지형은 방송 모드에서 사용하지 않고 바탕화면으로 돌아오면 다시 사용합니다. 플러그인이 그림 표시와 좌표 변환을 담당하며, 그림이 숨거나 창 뒤로 가리는 것은 자동 감지하지 않으므로 해당 지형을 갱신하거나 지워야 합니다.

PluginTestKit은 registerTerrain(name, rects), updateTerrain(name, rects), removeTerrain(name) 호출을 기록하고 이름 중복 및 종료 시 회수를 재현합니다. 충돌·그리기·엔진 틱은 재현하지 않습니다. 실행 예제는 발판 하나입니다.

5. 훅 — ctx.hook(id, (hook, current, ctx) -> …)

코어가 정하기 전에 묻습니다. 핸들러는 지금까지의 값 current 를 받아 새 값을 돌려주거나 null(통과)을 돌려줍니다.

규약:

  • 동기 — 부른 스레드에서 그 자리에서 돕니다. EDT·타이머·엔진 틱 위일 수 있으니 값싸게, 절대 블록하지 마세요. 20 ms 를 넘기면 훅+플러그인당 한 번 경고합니다.
  • 순서 — 모드 탭 순서로 위→아래, 아래가 이깁니다. 앞선 답을 존중하고 싶으면 current 를 보고 스스로 AND 하세요.
  • 형 — 기본값과 같은 형이어야 합니다(숫자는 Number). 아니면 통과 + 한 번 경고. 숫자 훅은 코어가 범위를 고정합니다(표의 clamp).
  • 예외 — 전부 잡습니다. 그 핸들러만 건너뛰고 체인은 계속됩니다. 아무도 답하지 않으면 기본값입니다. 등록된 핸들러가 없는 훅은 ctx Map 도 만들지 않고 기본값을 즉시 돌려줍니다.
  • 빈 문자열 — 뜻은 훅마다 다릅니다(표의 「반환·기본」): selftalk.line·speech.greeting 은 "" = 건너뜀, bubble.text 는 공백뿐인 답·null = 원문 그대로.
  • 사용자 약속 — 사용자가 건 약속(알람, 사용자가 누른 부탁, say.txt)은 훅으로는 막을 수 없습니다 — 그런 자리에는 취소 훅이 없고 미루기 훅만 있습니다. 앱이 스스로 고르는 것(혼잣말·인사)은 "" 로 건너뛸 수 있습니다.
  • ctx 는 불변 Map 이고 null 은 "" 입니다. 캐릭터가 있는 자리는 mascotId(Integer)·imageSet(String). 마스코트 객체는 넘기지 않습니다.

8. 호환 정책

  • 플러그인 API 의 공개 표면은 안정과 실험 둘로 나뉩니다. 표시가 없는 항목은 안정입니다. 실험 항목은 표에 「실험」 칩으로 표시되고 sdk.json 의 preview 에 같은 목록이 있습니다.
  • 안정 항목은 같은 api_version 안에서 더해지기만 합니다. 없어지지 않고 형이 바뀌지 않습니다. 결정 자리가 앱에서 사라진 훅은 기본값만 돌려주는 빈 자리로 남고 표에 폐기로 표시됩니다. 이벤트에는 키가 더해질 수 있고 빠지지 않습니다 — 모르는 키는 무시하세요.
  • 실험 항목은 api_version 을 올리지 않고 바뀌거나 없어질 수 있습니다. 그때는 CHANGELOG.md 에 적고, 없앤 자리는 한 앱 버전 동안 빈 자리로 남깁니다. 실험 항목이 앱 버전 하나를 바뀌지 않고 넘기면 안정으로 올립니다. 1.5.1 의 구분 기준: 자사 플러그인(LUMI Chat·Super Bongo)이나 앱 자체가 실제로 쓰는 문과 그 짝은 안정, 그 밖은 실험입니다.
  • api_version 은 안정 항목을 없애거나 모양을 바꿔야만 할 때 오릅니다. 그때 이행 목록을 CHANGELOG.md 에 적고, 직전 버전(N-1)을 위해 쓰인 플러그인은 한 버전 더 실립니다(없앤 훅은 빈 자리, 없앤 메서드는 위임 껍데기로). 두 버전 전 플러그인은 실리지 않고 업데이트 안내를 받습니다. 앱보다 새 api_version 을 적은 플러그인도 실리지 않습니다.
  • 「더해지기만 한다」는 뒤집으면 나중 앱 버전에서 더해진 메서드·훅·토픽이 같은 api_version 의 옛 앱에는 없다는 뜻입니다. 검증한 앱 버전을 plugin.json 의 app_version 에 적으세요. 실행 중인 앱과 다르면 모드 탭에 「N용」 칩이 붙습니다(안내일 뿐 막지 않습니다).
  • 약속 밖: 변환기가 건드리는 코어 클래스의 모양, PluginContext 와 이 문서의 타입 표 밖의 공개 클래스(클래스패스에 있어 부를 수는 있지만 버전마다 바뀔 수 있습니다), conf\settings.properties 의 앱 키.
  • (현재 버전 사실) 1.5.1 의 로더는 api_version 을 읽기만 하고 판단하지 않습니다. 위의 거부·칩은 다음 앱 버전부터 로더가 집행합니다.
  • SDK 버전은 앱 버전과 같습니다(sdk.json 의 sdk_version = app_version). api_version 은 별개의 호환 번호로 이 문서 제목에 적혀 있습니다. 문서·예제 개정 내용은 배포 안내에서 확인하세요.

10. 테스트 킷 — PluginTestKit

SDK 1.5.1의 beginMicCapture()도 가짜 백엔드에서 검사할 수 있습니다. beginMicCapture/endMicCapture 호출이 소유자 id와 함께 기록되고, lease 보유 중 speak는 speakSuppressed를 기록하며 재생 콜백을 호출하지 않습니다. kit.close()는 중첩 lease를 모두 반환합니다. 실제 오디오 장치는 열지 않습니다.

api_version은 호환 가능한 추가이므로 1을 유지합니다. 이 메서드가 없는 이전 앱도 지원하는 플러그인은 시작 시 메서드 존재를 확인하고 음성 입력만 비활성화해야 합니다. app_version은 표시용이며 최소 앱 버전을 강제하지 않습니다. SDK 1.5.1으로 컴파일했다는 사실만으로 이전 앱에 새 메서드가 생기지는 않습니다.

lib\Shimeji-ee.jar 는 게이트 때문에 앱을 띄울 수 없지만, 플러그인의 단위 검사는 앱 없이 됩니다. PluginTestKit 이 주는 PluginContext 는 문마다 이 킷으로 이어져 있어 — 플러그인이 한 일은 기록되고, 읽는 값은 가짜에서 오고, 이벤트·훅·시계는 검사가 직접 밉니다. 엔진·창·스팀은 하나도 안 뜹니다. tools\run_tests.py <플러그인 폴더> 가 test\*.java 를 굽고 돌립니다(예 examples\hello\test\HelloPluginTest.java; 프레임워크 없이 main 하나).

java
import com.group_finity.mascot.lumi.plugin.PluginTestKit;
import hello.HelloPlugin;
import java.nio.file.Path;

public final class HelloSmokeTest {
    public static void main(String[] args) throws Exception {
        Path manifest = Path.of(System.getProperty("plugin.dir"), "plugin.json");
        HelloPlugin plugin = new HelloPlugin();
        try (PluginTestKit kit = PluginTestKit.start(manifest)) {
            try {
                plugin.start(kit.context());
                kit.publish("ready");
                if (kit.calls("say").size() != 1) {
                    throw new AssertionError("Expected one startup greeting");
                }
                Object line = kit.ask("speech.greeting", "hi");
                if (!"[hello] hi".equals(line)) {
                    throw new AssertionError("Greeting hook failed: " + line);
                }
                kit.tick(60_000);
            } finally {
                plugin.stop();
            }
        }
    }
}

손대지 않은 hello 예제의 사본에 test\HelloSmokeTest.java 로 두고 python tools\run_tests.py <폴더> 로 돌리세요. 러너는 test\ 바로 아래의 *.java 만 찾고 클래스마다 JVM 을 따로 띄우며(-Dplugin.dir=<플러그인 폴더>), -ea 를 주지 않으므로 assert 문은 무효입니다 — 실패는 위처럼 AssertionError 를 직접 던지세요. 킷은 플러그인을 만들어 주지도, ready 를 내 주지도, stop() 을 대신 불러 주지도 않습니다 — 셋 다 검사가 합니다.

자주 불리는 훅에서 설정을 캐시하기

별도 진입 클래스 src\myplugin\QuietPlugin.java 로 두고, 쓸 때는 서비스 파일에 myplugin.QuietPlugin 을 적습니다. 매니페스트에는 "hooks": ["focus.quiet"] 을, settings 배열에는 {"key":"quiet","type":"bool","default":false,"label":"Keep quiet"} 을 더합니다.

java
package myplugin;

import com.group_finity.mascot.lumi.plugin.LumiPlugin;
import com.group_finity.mascot.lumi.plugin.PluginContext;
import com.group_finity.mascot.lumi.plugin.PluginPrefs;
import java.util.concurrent.atomic.AtomicBoolean;
import java.util.function.BiConsumer;

public final class QuietPlugin implements LumiPlugin {
    private final AtomicBoolean quiet = new AtomicBoolean();
    private PluginPrefs prefs;
    private BiConsumer<String, String> changed;

    @Override
    public void start(PluginContext ctx) {
        prefs = ctx.prefs();
        changed = (key, value) -> {
            if ("quiet".equals(key)) quiet.set(Boolean.parseBoolean(value));
        };
        prefs.onChange(changed);
        quiet.set(prefs.getBoolean("quiet", false));
        ctx.hook("focus.quiet", (hook, current, args) ->
                quiet.get() ? Boolean.TRUE : null);
    }

    @Override
    public void stop() {
        if (prefs != null && changed != null) prefs.removeOnChange(changed);
    }
}

훅은 원자적 캐시 값만 읽습니다 — 파일도, 설정 저장도, 저장소 잠금도 없습니다. 설정 변경 알림은 비동기라 바꾼 직후 잠깐 옛 값이 쓰일 수 있습니다. 리스너는 정상 종료든 시작 실패든 stop() 에서 직접 풉니다(§2).

시각 규칙 제작 — VisualLogic 실험 · CharacterDefinition 실험

공개 순수 엔진으로 GUI 미리보기와 본체 실행이 같은 규칙을 사용합니다. VisualLogic.read(Reader)는 UTF-8로 읽은 Properties 문자 스트림을 받아 Document를 반환합니다. Document(id, imageSet, variables, dialogues, rules)는 변경 불가능하며 생성 시 검증합니다. Dialogue(id, language, text, audio), Rule(id, event, variable, increment, comparison, threshold, dialogue, behavior)와 Effect(ruleId, dialogueId, text, audio, behavior)는 공개 record입니다. variables는 Map<String,Double>, dialogues는 ID별 Map<String,Dialogue>, rules는 순서가 있는 List<Rule>입니다.

schema=1
id=maker.example
imageSet=MM_example
variable.clicks=0

dialogue.hello.text=안녕하세요
dialogue.hello.audio=sound/maker.example/hello.wav

new VisualLogic.Session(document) 뒤 dispatch(event)가 List<Effect>를 반환합니다. 이벤트는 ready, click, menu:<식별자>입니다. 매칭 규칙을 문서 순서대로 실행하며 변수 증가 후 always/eq/ne/lt/le/gt/ge로 비교합니다. 변수·대사·행동은 빈 문자열로 생략할 수 있습니다. 변수를 생략하면 증가값은 0, 조건은 always여야 합니다. 다른 이벤트는 빈 결과입니다. variables()는 복사본, restore(Map<String,Double>)는 알려진 변수만 복원하며 잘못된 값은 전체 복원을 거부합니다. null은 허용하지 않습니다. close() 후 변경·실행은 거부합니다. 증가 연산 넘침은 변수 변경과 효과를 모두 취소합니다.

식별자는 영숫자로 시작하는 영숫자·점·밑줄·하이픈 1~64자입니다. 입력 100만 문자, 변수 128개, 대사 256개, 규칙 128개, 대사 4096자, 숫자 유한값 ±1e12 이내입니다. 대사 language는 32자 이내 메타데이터이며 명시적으로 선택한 대사를 번역하지 않습니다. audio는 sound/ 아래 상대 WAV 경로이며 상위 이동을 허용하지 않습니다. 스크립트·반복·재귀·파일/네트워크 동작은 없습니다.

패키지의 plugins/runtime/visual-logic.properties는 JAR 없이도 본체가 발견합니다. 실행 코드로 분류되어 승인·변경 시 재승인·다음 실행 적용과 보호된 실행 사본을 따릅니다. 미승인 모드는 PNG/WAV까지 적용하지 않습니다. 본체 어댑터는 지정 imageSet의 click만 받으며 클릭 간격은 100ms 이상입니다. 메뉴 이벤트마다 트레이 항목을 등록합니다. 대사는 5초 말풍선, WAV는 본체 효과음 설정, 행동은 해당 캐릭터가 제공하는 이름만 사용합니다. 변수는 모드 설치 출처별 설정에 분리되어 정상 종료 때 저장되고 재시작 때 복원됩니다. 비정상 종료 후에는 마지막 정상 종료 값입니다. 모드 ID 문자열만으로 다른 모드 상태를 공유하지 않습니다.

CharacterDefinition.generate(String imageSet, List<Frame>)는 Map<String,String>으로 img/<imageSet>/conf/actions.xml, behaviors.xml, info.xml을 반환합니다. Frame(String image,int durationMs,int anchorX,int anchorY)의 image는 이미지셋 안의 PNG 상대 경로입니다. 1~4096개 프레임, 16~60000ms, 앵커 ±8192를 허용하며 내장 이미지셋 이름은 거부합니다. 지속시간은 60Hz 엔진 tick으로 반올림합니다. PNG는 호출자가 내보냅니다. 자체 프레임으로 ModMakerIdle/Stand/Walk/Fall/Dragged/Thrown/ChaseMouse 기본 행동을 생성합니다. 이 API는 파일을 설치하거나 덮어쓰지 않습니다. Steam 게시 API는 포함하지 않습니다.

CharacterDefinition.behaviorNames()는 생성 행동 이름의 변경 불가능한 Set<String>을 반환합니다. 편집기는 이 기본 집합과 선언한 커스텀 행동으로 선택을 검증합니다. 알 수 없거나 중복된 Properties 필드, 불완전한 대사 레코드는 거부합니다.

실제 본체 제작 시험 — AuthoringPreview 실험

PluginContext.openAuthoringPreview(AuthoringPreview.Snapshot) · 실험은 실행 중인 데스크톱 본체에 제작 시험 전용 캐릭터 한 개를 만들고 AuthoringPreview.Session을 반환합니다. 플러그인 컨텍스트마다 열린 세션 하나만 허용합니다. 제작기에서 사용자가 시험 시작을 선택한 뒤 호출하며, 모드 설치·코드 승인·일반 소환 목록·영구 변수 저장은 변경하지 않습니다. PluginTestKit에서는 UnsupportedOperationException을 던집니다. 해제된 컨텍스트 또는 이미 열린 세션에서는 IllegalStateException을 던집니다.

  • Frame(byte[] png,int durationMs,int anchorX,int anchorY)는 PNG 바이트, 16~60000ms와 ±8192 앵커를 받습니다. 입력·반환 바이트 배열을 복사합니다.
  • Snapshot(List<Frame>,VisualLogic.Document,Map<String,byte[]> audio)는 규칙과 필요한 이미지를 함께 전달합니다. 음성 키는 규칙 대사의 sound/...wav 상대 식별자입니다. 실제 파일 경로를 읽는 요청이 아니며, 경로·XML·스크립트·JAR를 받지 않습니다. 모든 음성 참조가 audio에 있어야 하고 행동은 CharacterDefinition.behaviorNames() 안에 있어야 합니다.
  • 한 스냅샷은 1~16384개 PNG 프레임, 최대 256개 WAV, 파일당 4MiB, 전체 24MiB를 허용합니다. PNG는 가로·세로 각각 최대 2048, 전체 1600만 픽셀입니다. 음성은 PCM WAV, 1~2채널, 최대 96kHz·30초입니다. 바이트·형식 검증 실패는 예외로 반환됩니다.
  • Session.replace(Snapshot)는 수정본 전체를 검증한 뒤 시험 캐릭터를 교체합니다. 위치는 유지하고 변수는 초기값으로 돌아가며 ready를 실행합니다. 거부된 수정본은 기존 시험 상태를 보존합니다.
  • Session.dispatch(String)는 ready, click 또는 현재 문서에 선언된 menu:<식별자>를 실행합니다. 실제 시험 캐릭터 클릭도 규칙에 전달됩니다. 닫힌 세션이나 선언하지 않은 이벤트는 거부합니다.
  • Session.state()는 State(boolean closed,int mascotId,long revision,Map<String,Double> variables,List<String> trace) 복사본입니다. 변수와 최근 실행 기록을 읽습니다. 기록은 최대 80줄·줄당 512자로 제한하며 어느 스레드에서나 조회할 수 있습니다.
  • 열기·교체·이벤트 실행은 Swing EDT 밖에서 호출합니다. close()는 반복 호출할 수 있으며, EDT에서는 정리를 예약하고 다른 스레드에서는 정리가 끝날 때까지 기다립니다. 제작기 종료 시 호출합니다. 플러그인 컨텍스트 해제도 세션을 정리합니다. 시험 캐릭터·말풍선·음성·자체 임시 파일은 세션 소유입니다.

시험 상태는 저장 프로젝트나 내보낸 모드에 기록되지 않습니다. 영구 설치·승인·본체 재시작 시험은 내보내기 흐름에서 별도로 수행합니다.

행동별 프레임 (실험)

CharacterDefinition.Behavior(String name,String kind,List<Frame> frames)와 generateBehaviors(String imageSet,List<Behavior>)는 행동마다 별도 PNG·지속시간·앵커를 제공합니다. 이름은 [A-Za-z][A-Za-z0-9_-]{0,63}, kind는 behaviorNames()의 기본 동작 이름입니다. 커스텀 포즈에는 ModMakerIdle kind를 사용합니다. 기본 이름은 같은 kind만 허용하고 중복 이름은 거부합니다. ModMakerIdle이 필수이며 빠진 기본 엔진 행동은 대기 프레임을 사용합니다. 최대 512개 행동·행동당 4096개 프레임·총 16384개 프레임입니다. 기존 generate는 동일하게 동작합니다. behaviorNames()는 기본 이름만 반환하므로 편집기는 자체 행동 이름을 추가하여 검증합니다.

AuthoringPreview.Behavior(String name,String kind,List<Frame> frames)와 Snapshot(frames,document,audio,behaviors)는 같은 계약으로 실제 엔진에 행동별 이미지를 전달합니다. behaviors가 비어 있으면 기존 frames를 공통 사용하고, 있으면 behaviors가 실제 이미지 원본입니다(frames에는 기본 대기 목록을 전달). 전체 행동 합계 16384개 프레임·24 MiB·디코딩 1,600만 픽셀 예산을 공유합니다. 기존 3인자 Snapshot도 유지됩니다. 선언된 커스텀 행동을 규칙에서 참조할 수 있고 잘못된 스냅샷은 기존 세션을 보존합니다. 동의·수명·파일 접근 계약은 변하지 않습니다.

generateBehaviors(String imageSet,List<Behavior>,String previewImage)는 선택적인 대표 PNG 경로를 받습니다. null은 첫 대기 프레임을 그대로 사용합니다. 경로는 이미지셋 내부 PNG 상대 경로이며 절대 경로·상위 경로·XML 문자는 거부합니다. 호출자가 해당 PNG를 함께 내보내야 합니다. 이 값은 info.xml의 PreviewImage에만 반영되어 본체 캐릭터 선택창에서 사용되며 행동 프레임을 바꾸지 않습니다. 모드 목록이나 Steam 썸네일 설정은 아닙니다.

설치된 LUMI 행동 템플릿

CharacterTemplates.behaviors()는 설치된 Lumi XML의 행동 그래프에서 Template(id,displayName,frames)를 읽습니다. TemplateFrame(slot,image,durationMs,anchorX,anchorY)의 slot은 불투명 포즈 식별자, image는 lumi:shime1.png 형태의 본체 참조입니다. CharacterTemplates.image(reference)는 최대 4 MiB PNG 원본을 반환합니다. 경로를 외부로 노출하지 않으며 잘못된 참조는 IllegalArgumentException, 본체 콘텐츠 누락은 IllegalStateException입니다. 리소스 풀이나 배포 PNG에 복제하지 마세요.

CharacterDefinition.Frame의 마지막 templatePose, Behavior의 마지막 templateId는 이전 생성자에서는 빈 문자열입니다. 템플릿 내보내기는 원본 조건·복합 액션·속도·핫스팟·다음 행동을 보존하고 포즈만 교체합니다. 원본 포즈 키가 빈 새 프레임은 앞 프레임의 애니메이션(맨 앞이면 첫 애니메이션)에 추가됩니다. 각 애니메이션 안의 순서는 입력 순서이며 조건 애니메이션 사이의 이동은 하지 않습니다. 변경하지 않은 Duration 표현식은 그대로 보존합니다. 출력 @lumi/ 이미지는 본체가 설치된 Lumi 파일로 해석하며 PNG를 패키지에 복사하지 않습니다. 최대 512행동, 16384프레임입니다.

AuthoringPreview.Frame(png,durationMs,anchorX,anchorY,hostImage,templatePose)와 Behavior(name,kind,frames,templateId)는 같은 계약으로 실제 실행기에서 시험합니다. hostImage가 있으면 PNG 바이트 대신 본체 참조를 사용합니다. 이전 생성자는 유지됩니다. 설치·승인·게시 동작은 없습니다.

CharacterTemplates.reservedIds()는 원본 행동 및 보조 액션 ID 집합입니다. 자신의 templateId와 일치하는 ID 및 동일 kind의 기존 7개 기본 역할을 제외한 이름 충돌은 내보내기에서 거부합니다. 표시 이름과 별개인 실행 ID 편집 시 이 집합을 예약하세요.

같은 templateId의 여러 실행용 별칭은 kind와 전체 프레임 정의가 동일할 때 허용합니다. 충돌하는 덮어쓰기는 거부합니다. 예를 들어 사용자 ID Idle과 엔진 역할 ModMakerIdle은 같은 StandUp 템플릿을 공유할 수 있습니다. 실시간 미리보기에서도 PNG 내용을 공유하며 원본 복합 동작을 유지합니다.

필수 행동과 행동 효과음

CharacterTemplates.requiredBehaviorIds()는 엔진 필수 실행 ID ChaseMouse, Fall, Dragged, Thrown을 반환합니다. Template.required()도 같은 분류를 제공합니다. 제작기의 기본 대기 역할은 이 집합과 별개이며 이전 생성자는 유지됩니다.

CharacterDefinition.Behavior(name,kind,frames,templateId,sound) 및 AuthoringPreview.Behavior의 같은 생성자에서 sound는 sound/<modid>/<file>.wav 패키지 상대 경로입니다. null 또는 빈 문자열은 기본 템플릿 효과음을 유지합니다. 지정한 WAV는 원본 포즈 소리보다 우선하여 행동에 진입한 뒤 첫 재생 틱에 한 번 울리며 같은 행동의 애니메이션 반복으로 다시 울리지 않습니다. 행동을 새로 시작하면 다시 재생할 수 있습니다. 소리 끄기·개별 음소거·전체 음량 설정은 기존 효과음과 같습니다.

생성 결과에 img/<imageSet>/conf/behavior-sounds.properties가 추가될 수 있습니다. 이 파일도 반환된 다른 파일과 함께 내보내야 합니다. 원본 XML·이동·조건·포즈 Sound는 변경하지 않으므로 override를 제거하면 원래 효과음으로 돌아갑니다. 별칭은 효과음까지 동일해야 같은 템플릿을 공유할 수 있습니다. 실시간 미리보기의 WAV 바이트는 기존 Snapshot.audio 맵에 같은 키로 제공하며 참조 누락은 거부합니다. 편집기에서 삭제된 선택적 WAV는 override를 전달하지 않아 기본 효과음을 유지할 수 있습니다. 패키지에 WAV가 실제로 없으면 소리 재생만 실패하며 캐릭터 동작은 계속됩니다.

Template.hasDefaultSound()는 해당 설치본 행동의 도달 가능한 액션 그래프 전체에서 비어 있지 않은 Pose.Sound가 있는지 나타냅니다. 조건별 애니메이션도 포함하며, 값이 false인 행동은 기본 소리가 없는 것으로 표시할 수 있습니다. 파일의 존재·디코딩 성공이나 현재 음소거 설정을 뜻하지 않습니다. 이전 수동 생성자는 소리 메타데이터를 모르는 경우 false로 유지하고, behaviors()의 결과가 설치본의 정본입니다.

안내 에셋이 없는 최종 내보내기

generateStandaloneBehaviors(imageSet, behaviors, previewImage)는 최종 패키지용입니다. 작성한 행동의 액션·조건 그래프와 behaviorNames()의 7개 실행 역할만 유지합니다. 작성하지 않은 역할은 자신의 기본 대기 프레임으로 보완하며 Stand/Walk를 임의의 자율 행동으로 추가하지 않습니다. 작성하지 않은 다음 행동 참조는 기본 대기 또는 작성한 템플릿의 실행 ID로 연결하고, 연결할 대상이 없는 핫스팟은 제거합니다.

작성 프레임·썸네일의 lumi: 이미지 참조와 활성 그래프에 남은 기본 Lumi 소리는 최종 내보내기에서 거부합니다. 기본 소리가 있으면 사용자 WAV를 연결하거나 명시적으로 무음으로 설정해야 합니다. 기존 generateBehaviors는 편집·가이드 미리보기 호환을 위해 그대로 유지됩니다.

CharacterDefinition.Behavior 및 AuthoringPreview.Behavior의 여섯 번째 인자는 boolean muteDefaultSound이며 기존 생성자는 false입니다. 빈 sound와 true의 조합은 기본 소리를 끕니다. 이때 매핑 파일의 빈 값은 명시적 무음을 뜻하고, 키가 없으면 기본 소리를 유지합니다. 최종 생성 결과는 꼬미 원음 참조를 제거하지만 해당 행동의 이동·조건·프레임 설정은 보존합니다. 삭제된 선택적 사용자 WAV를 무음으로 내보내려면 이 플래그를 사용하세요.

공유 기본 액션 제작 — 새 25Hz API

CharacterTemplates.actions()는 ActionTemplate(id,displayName,frames,hasDefaultSound) 목록입니다. named Action이 직접 소유한 Animation만 읽으며 Sequence의 하위 시나리오를 펼치지 않습니다. 따라서 Walk·Run·Stand·Sit 등의 프레임 정의는 한 곳입니다. 프레임 슬롯은 Action/animationIndex/poseIndex, 시간은 실제 엔진의 25Hz(40ms/틱)입니다. CharacterDefinition.actionTickDurationMs(ms)로 표시·미리보기 시간을 같은 틱으로 맞출 수 있습니다. 구 Behavior API의 60 기준 변환은 호환을 위해 그대로 유지되며 새 제작기는 이 액션 API를 사용합니다.

CharacterDefinition.Action(name,templateId,frames,sound,muteDefaultSound)와 generateActions(imageSet,actions,previewImage)는 공유 액션을 편집합니다. 기본 작성 액션은 name Idle이며 꼬미 원본을 쓰면 templateId Stand입니다. templateId가 빈 커스텀 액션은 독자적인 정지 포즈로 생성합니다. 모든 액션이 커스텀인 프로젝트는 설치된 Lumi XML 없이 생성할 수 있습니다. generateStandaloneActions는 작성한 액션의 안내 이미지·소리를 거부하고, 작성하지 않은 원본 액션/인라인 포즈는 자체 Idle 이미지와 무음으로 보완하여 기존 시나리오의 이동·조건을 유지합니다. 빠진 7개 실행 역할도 자체 대기로 보완합니다.

원본 Action ID는 바꾸지 않으므로 Walk를 한 번 편집하면 WalkLeftAlongFloorAndSit·WalkAlongWorkAreaFloor 등의 모든 참조에 반영됩니다. 새 액션 ID로 호출할 수 있는 Behavior도 만듭니다. 새 호출 진입점은 별도 wrapper에만 기본 이동 목표와 최대 100틱을 제공하고 끝나면 Idle로 돌아갑니다. 같은 이름의 기존 기본 Behavior는 원래 문맥을 유지합니다. 원본 시나리오의 ActionReference 파라미터는 변경하지 않습니다. 바닥·벽·천장 등 원본 액션의 실행 환경 조건도 유지됩니다.

효과음은 conf/action-sounds.properties로 물리 액션 ID에 연결하며 동일 Behavior 안에서 같은 Action이 재진입해도 한 번씩 재생합니다. 같은 클립이 아직 재생 중이면 새 진입 시 처음부터 재생합니다. 빈 값은 명시적 무음, 없는 키는 원래 포즈 소리입니다. AuthoringPreview.Action은 같은 필드를 사용하며 Snapshot.forActions(actions,document,audio)로 실시간 시험합니다. 기존 Frame 필드와 audio 맵 키는 그대로입니다. 레거시 behaviors와 새 actions를 한 Snapshot에 동시에 넣을 수 없습니다.

새 프레임의 slot이 비어 있으면 직전 원본 Animation(첫 프레임이면 첫 Animation)에 넣고, 해당 Animation의 원본 포즈를 바탕으로 Velocity 등 이동 파라미터를 유지합니다. 기존 슬롯을 다른 조건 Animation으로 옮기는 순서는 거부합니다.

프레임 효과음 — 공유 액션 API

TemplateFrame은 기존 5개 필드 뒤에 sound와 volumeDb를 제공합니다. 원음 참조는 lumi:<상대경로>.wav, 없으면 빈 문자열입니다. CharacterTemplates.sound(reference)는 설치본 img/Lumi/sound 아래 WAV를 4 MiB까지 읽습니다. 임의 경로·상위 이동은 거부하며 잘못된 참조는 IllegalArgumentException, 파일 읽기 실패는 IllegalStateException입니다. 안내 원음은 사용자 리소스에 복사하지 마세요.

CharacterDefinition.Frame의 기존 5개 필드 뒤, AuthoringPreview.Frame의 기존 6개 필드 뒤에 sound, muteDefaultSound, loopSound가 추가됩니다. 이전 생성자는 빈 sound/false/false입니다. 사용자 sound는 sound/...wav 패키지 경로이며 빈 값은 원음을 상속합니다. mute는 소리를 제거합니다. 기본 once는 프레임 진입마다 한 번 재생하며 애니메이션이 다시 돌아오면 다시 재생합니다. loop는 프레임 동안 반복하고 프레임·애니메이션·행동 이탈 또는 캐릭터 제거 때 중지합니다. once의 잔향은 다음 프레임에서도 끝까지 재생하되 캐릭터별 최대 16개로 제한합니다. 캐릭터마다 Clip을 소유해 서로의 소리를 끊지 않습니다.

frame-sounds.properties의 <cue>.path·<cue>.loop가 XML의 Sound="@frame/<cue>.wav"와 연결됩니다. 이 파일도 함께 내보내세요. 원음의 Volume은 유지하고 사용자 WAV 교체는 0 dB를 사용합니다. 기존 액션 단위 효과음/무음이 지정되면 그 설정이 우선합니다. 새 제작기는 프레임 설정을 사용합니다.

직접 Animation 안의 이미지·반전 이미지·기준점·이동 등 속성이 같은 양의 정수 tick 구간은, 뒤 Pose에 새 Sound 선언이 없을 때 논리 프레임 하나로 표시합니다. 범위 slot은 Action/animationIndex/start-end입니다. Walk는 4개×240ms, Run은 4개×120ms이며 소리 시작 위치는 유지합니다. 새 XML은 이 논리 프레임당 Pose 하나를 내보내며 별도 진입 정책으로 기존 1 tick 요청+무음 hold 분할 없이 재트리거를 막습니다. 기존 단일 slot도 읽습니다. 최종 내보내기의 안내 PNG/WAV 금지 원칙은 동일합니다.

프레임의 마지막 선택 인자 Double soundVolumeDb는 내장 WAV를 사용자 리소스로 포함할 때 원래 음량을 보존합니다. 유한한 -80..24 dB만 허용합니다. null은 기존 정책(원음 음량 상속, 사용자 WAV는 0 dB)을 유지하며 기존 생성자는 호환됩니다.

공통 모션 제작

CharacterTemplates.motions()는 실제 Behavior 진입점에서 도달 가능한 실행 액션을 SDK의 의미별 바인딩 정본으로 묶습니다. MotionTemplate(id,displayName,frames,bindings,hasDefaultSound)의 첫 binding이 대표 애니메이션입니다. 미사용 액션은 제외되며 나머지 사용 액션도 단일 binding 모션으로 제공합니다. Jump는 Jumping, FaceGlide는 FaceGlideMid, Land는 SoftLandSilent가 대표입니다. CharacterDefinition.Motion(name,templateId,frames)를 generateMotions(imageSet,motions,previewImage) 또는 generateStandaloneMotions(...)에 전달합니다. templateId는 모션 ID이며 빈 값은 커스텀, name=Idle은 필수입니다. 프레임 slot은 대표 native 액션의 slot을 유지합니다. 편집 이미지·시간·기준점·효과음·음량은 모든 binding에 동일하게 적용되고, 원본 액션의 클래스·목표·중력·참조 Duration·조건·프레임 이동값은 각 실행 액션에 남습니다. 역할별 원래 효과음 차이도 대표 효과음으로 통일합니다. 프레임을 추가하면 해당 애니메이션의 첫 물리 pose를 사용합니다. 조건부 애니메이션을 가로지른 순서 변경은 거부합니다. AuthoringPreview.Motion(name,templateId,frames)와 Snapshot.forMotions(motions,document,audio)는 같은 설정으로 실시간 시험합니다. Snapshot.motions()로 읽으며 actions/behaviors와 혼합할 수 없습니다. 모션 name으로 callable Behavior를 생성하므로 이벤트가 모션을 직접 선택할 수 있습니다. 기존 Action/Behavior API와 생성자는 유지됩니다. 이미지·음성 가이드 참조는 미리보기에서만 허용하고 최종 내보내기에서는 교체·포함 또는 음소거해야 합니다.

Walk는 Walk/ChatApproach/LeadParade/JoinParade/GatherJoin/HiFiveApproach/GiftApproach, Dash는 Dash/CreditDash/TagDashLeg/TagChase에 공통 적용합니다. 대표 Walk/Dash의 효과음도 공유하므로 원래 무음인 실행 장면에 발소리가 추가되는 것은 의도된 정책입니다.

효과음 재생 범위

CharacterTemplates.SoundPlayback은 FRAME_ENTRY(프레임/애니메이션 주기 진입마다)와 BEHAVIOR_ENTRY(한 행동 실행 중 같은 논리 음원은 한 번)를 제공합니다. TemplateFrame 마지막 인자 soundPlayback은 원본 SoundGate에서 발소리 등 반복 허용 음원은 FRAME_ENTRY, pinch 등 비반복 음원은 BEHAVIOR_ENTRY입니다. 슬롯 원본액션/애니메이션번호/자세번호의 애니메이션 번호가 다르면 순차 프레임이 아닌 조건부 분기일 수 있습니다. Pinched의 29개 분기는 하나의 행동에서 선택되는 대안입니다. CharacterDefinition.Frame과 AuthoringPreview.Frame에 마지막 선택 인자 CharacterTemplates.SoundPlayback soundPlayback을 추가했습니다. null은 대표 원본 정책을 상속하고 커스텀 프레임은 FRAME_ENTRY를 사용합니다. 명시 값은 상속을 덮어씁니다. loopSound=true는 이 범위보다 우선합니다. 내장 WAV를 리소스로 포함할 때 음량과 함께 이 값을 프로젝트에 보존하고 전달해야 합니다. 프레임 sidecar의 .scope가 이 값을 보존합니다. 과거 sidecar에 scope가 없으면 FRAME_ENTRY입니다. BEHAVIOR_ENTRY는 캐릭터별 실제 행동 episode와 .path 논리 음원을 기준으로 하므로 분기·1프레임 반복으로 재생하지 않고, 놓았다 다시 잡으면 재생합니다. 종료된 세션과 다른 캐릭터의 gate는 공유하지 않습니다. 스톡 캐릭터의 기존 SoundGate 정책은 수정하지 않습니다.

Pinched는 조건부 29분기가 아닌 중립 Pinched/14/0 한 자세입니다. generateLimitedMotions/generateStandaloneLimitedMotions(imageSet,motions,previewImage)와 AuthoringPreview.Snapshot.forLimitedMotions(motions,document,audio)를 사용합니다. Snapshot.limitedRuntime()으로 프로필을 확인합니다. 기존 모든 생성 경로는 변경하지 않습니다.

명시 이벤트로 Pinched를 선택하면 그림을 한 번 재생하는 유한 모션입니다. 실제 잡기 물리는 별도 내부 액션이 동일 애니메이션을 사용하며, 이벤트 호출이 마우스를 붙잡지 않습니다. 요청한 내장 템플릿이 설치본에 없으면 커스텀으로 조용히 대체하지 않고 오류를 반환합니다.

종료 이벤트 (exit)

시각 규칙의 event는 ready, click, exit, menu:<id>를 지원합니다. exit는 캐릭터 제거 및 정상 앱 종료 전 해당 캐릭터에게 한 번 발생합니다. 조건 불충족·빈 반응은 지연 없이 제거합니다. 모션·대사·음성이 있으면 모든 캐릭터가 동시에 최대 2초의 반응 단계를 거친 뒤 정리합니다. 명시 모션은 최소 캐릭터 프로필이 생성한 위치 고정 시각 액션으로 재생하므로 공중·집기 중에도 안전합니다. 긴 모션/음성은 2초에서 잘립니다. behavior가 빈 값이면 현재 모션의 신원·시간·일시정지 상태를 유지하며 새 모션 명령을 내리지 않습니다. AuthoringPreview.Session.dispatch("exit")는 즉시 반환하며 실제 반응 후 state().closed()가 true가 됩니다. 종료 중 replace/추가 dispatch는 무시합니다. Session.close·미리보기 교체·모드 비활성화는 exit를 발생시키지 않고 즉시 취소/정리합니다. 중복 제거/종료 요청은 동일한 반응 Future를 공유합니다. 준비·UI가 막혀도 별도 deadline이 제거 상태를 확정하며 EDT에서 기다리지 않습니다. 물리 스피커 장치 실패 시 음성만 생략하고 유효한 모션/대사는 유지합니다. 참조 WAV가 없고 다른 효과도 없으면 지연하지 않습니다.

기본 자동 애니메이션 제작

CharacterTemplates.automaticAnimations()는 Stand(Idle), Walk, Run, Jump, Falling, Land, Pinched, Sit, Sprawl, GrabWall, ClimbWall, GrabCeiling, ClimbCeiling을 제공합니다. 사용자는 프레임 이미지·시간·기준점·효과음만 작성하고 실행 조건과 이동은 엔진이 관리합니다. 벽·천장은 창과 작업영역 지형을 사용합니다. 잡힘은 중립 자세, 벽 애니메이션은 한 가지 기본 자세로 편집합니다. 벽 잡기·오르기의 기준점은 화면 끝 벽을 기준으로 편집하며, 창 옆면에서는 원본 템플릿의 창/화면 기준점 차이를 추가합니다. 작성한 기준점 수정량은 두 경우에 동일하게 유지됩니다. 왼쪽·오른쪽 방향의 반전과 현재 접촉 중인 창 판정은 엔진이 처리합니다.

CharacterTemplates.automaticAnimationIds()는 설치 에셋을 읽지 않고 지원 ID 목록을 반환합니다. 기본 13종에 HardLand, Stunned, Bouncing, GetUpHop, LookAround, TiltHead, SitAndDangleLegs, AlarmNotice, Farewell, HappyHop, HeadPat을 더해 24종입니다. 프레임 슬롯과 bindings는 SDK 소유 식별자이며 호출자는 해석하거나 네이티브 XML 구조에 대입하지 않습니다.

  • 낙하·던져짐: 바닥에 닿은 낙하 높이가 550을 넘으면 등록된 HardLand → Stunned → GetUpHop을 순서대로 실행합니다. 이 세 항목 중 하나도 없으면 다음 갈래를 검사합니다. 높이가 320을 넘고 Bouncing이 있으면 같은 애니메이션으로 두 번 튑니다. 나머지는 Land, 미등록이면 Idle입니다. 높이는 엔진 좌표를 사용하며 사용자가 임계값을 설정하지 않습니다. 벽에 붙은 상태는 착지로 처리하지 않습니다.
  • LookAround, TiltHead, SitAndDangleLegs, HappyHop은 바닥의 자동 선택 후보입니다. HappyHop은 같은 시각 타임라인으로 두 번 뛰며 앱의 호감도 상승·바로가기 동작 요청도 받습니다. GetUpHop/Bouncing은 프레임 수나 재생 길이에 관계없이 엔진의 도약·착지 물리를 따릅니다.
  • AlarmNotice는 알람·정각 알림 요청에만 연결됩니다. 등록된 캐릭터에만 유지 시간을 부여하고, 벽·천장에서는 먼저 낙하한 뒤 재생합니다. 짧은 프레임 열도 알림 유지 중 계속 순환하며 사용자 조작과 앱의 종료 규칙을 따릅니다.
  • Farewell은 기존 정상 종료 인사 과정에 연결되며 일반 Chatter 요청과 분리됩니다. 집중·화면 점유 등 기존 앱의 인사 생략 규칙과 종료 시한을 유지합니다. 공중에서도 사용자 그림으로 재생하며 진행 중인 알람에 가려지지 않습니다. 미등록이면 종료 애니메이션을 추가하지 않습니다.
  • HeadPat은 그림 상단 중앙(가로 1/6–5/6, 세로 위 절반)을 자동 입력 영역으로 사용합니다. 문지르기·길게 누르기는 기존 앱이 판정하며 방향별 파라미터를 작성하지 않습니다. 등록한 한 타임라인을 유지하고 손을 뗀 뒤 HappyHop이 있으면 사용하고, 없으면 Idle로 돌아갑니다. 몸통 클릭은 기존 들기 동작을 유지합니다.

조건식·이벤트 편집이나 런타임 플러그인을 내보내지 않습니다. 미등록 선택 애니메이션을 꼬미 가이드로 보완하지 않으며 기존 일반/limited 캐릭터와 꼬미의 동작 규칙은 유지합니다. 다른 캐릭터, 정원·봉고·게임·변신, 마우스 추적 전용 경로, 창 던지기 같은 특수 조건 동작은 목록에 포함하지 않습니다.

CharacterDefinition.generateAutomaticAnimations(imageSet,animations,previewImage)와 generateStandaloneAutomaticAnimations(...)는 기존 Motion/Frame DTO를 받습니다. Idle은 필수이며 templateId는 비어 있거나 Stand입니다. 나머지는 제공 카탈로그의 ID와 name/templateId가 같아야 합니다. 커스텀 시나리오는 거부합니다. 미작성 선택 항목은 실행하지 않고, 낙하·잡힘 누락은 무음 기본 대기로 보완합니다. 프레임 개수/그림 교체가 이동을 막지 않도록 걷기·달리기·벽/천장 이동 속도는 엔진이 설정합니다. 바닥 후보는 지상에서, 벽·천장 후보는 해당 경계에서만 선택하며 공중에서는 낙하로 복귀합니다.

결과는 actions.xml/behaviors.xml/info.xml과 character-profile.properties, 필요한 프레임 효과음 메타데이터입니다. 이벤트·대사 로직과 종료 애니메이션 별칭을 만들지 않습니다. standalone은 꼬미 가이드 이미지를 거부합니다. AuthoringPreview.Snapshot.forAutomaticAnimations(animations,audio)는 동일 프로필을 실제 엔진에서 시험하며 이벤트 문서를 받지 않습니다. Snapshot.automaticRuntime()으로 구분합니다. 기존 생성기와 플러그인 이벤트/대사 API는 유지됩니다.

자동 생성기의 imageSet은 프로젝트 폴더명으로 사용할 수 있습니다. CharacterDefinition.validAutomaticImageSetName(name)은 1~64 UTF-16 코드 단위의 유효한 Windows 단일 폴더명을 검사합니다. 한글·공백·유효한 유니코드·허용된 문장부호는 원문 그대로 유지하며 trim, 대소문자 변경, 유니코드 정규화를 하지 않습니다. 빈 이름, 경로 구분자, <>:"/\\|?*, 제어문자, 잘못된 서로게이트, XML에서 허용하지 않는 U+FFFE/U+FFFF, 끝 공백/점, 캐릭터 선택기가 숨기는 선행점 이름, Windows 장치 예약명(확장자와 COM/LPT의 상첨자 숫자 변형 포함), Lumi/Credit/Unused는 거부합니다. 생성 함수는 동일 규칙으로 검증하며 info.xml의 표시명은 XML 텍스트로 이스케이프합니다. 이 이름은 img/<imageSet>/ 디렉터리명이며 플러그인·모드 식별자의 ASCII 계약은 바뀌지 않습니다. 기존 일반/limited 생성기도 기존 이름 계약을 유지합니다.

연계 애니메이션 조회와 전체 활동 시험

AnimationActivities.forAnimation(animationId, registered)는 선택한 애니메이션이 쓰이는 활동 목록을 반환합니다. registered에는 현재 작성한 애니메이션 ID를 넣습니다. Idle과 기본 템플릿의 Stand는 같은 기본 대기로 취급합니다. 이 조회는 에셋을 가져오거나 프로젝트에 애니메이션을 등록하지 않습니다.

  • Activity(id, roles, related, participantCount, available)는 활동 ID, 역할별 단계, 함께 쓰는 자세, 필요한 전체 캐릭터 수를 제공합니다. available은 등록 조합으로 활동을 만들 수 있는지를 뜻하며 실제 지형이나 상대 상태를 보증하지 않습니다.
  • Role(id, steps)는 한 역할의 논리적 단계 순서입니다. 이동·접촉·조건 분기·반복은 본체가 처리하므로 이 목록을 고정 시간표나 임의의 행동 호출 스크립트로 해석하지 않습니다.
  • Step(id, animationId, effectiveAnimationId, muted, skipped)는 편집 슬롯과 실제 사용할 그림의 슬롯을 구분합니다. 대체 우선순위는 본체 생성기와 공유합니다. skipped이면 단계가 생략되고 effectiveAnimationId는 비어 있습니다. muted는 본체가 강제로 무음 처리하는 경우이며 작성자가 설정한 음소거와 별개입니다.

자동 애니메이션 시험 세션의 startActivity(activityId)는 그 세션 소유 캐릭터와 동료를 이용해 실제 엔진의 활동을 시작합니다. pauseActivity(true/false)로 일시정지/계속, stopActivity()로 중지합니다. 모두 EDT 밖에서 호출합니다. activityState()의 ActivityState(activityId, phase, actors, reason)을 읽어 현재 상태를 표시합니다. ActivityActor(mascotId, roleId, animationId, stepId)는 실제 실행 중인 역할과 단계를 알려주며, 알려진 단계 밖이면 빈 ID가 올 수 있습니다. 시간 경과만으로 다음 단계가 성공했다고 추정하지 않습니다.

상태는 IDLE, RUNNING, PAUSED, COMPLETED, CANCELLED, FAILED입니다. COMPLETED만 정상 완료이며 조건 부족·상대 부재·중단·시간 초과는 구분합니다. 세션 교체·닫기·플러그인 종료에서는 활동과 세션 소유 소품/효과음을 정리합니다. 일반 캐릭터나 다른 세션의 행동, 사용자의 기능 설정은 바꾸지 않습니다. 이 API는 임의의 본체 행동 이름이나 코드 실행을 받지 않습니다.

java
var activities = AnimationActivities.forAnimation("HiFive", registeredIds);
var activity = activities.stream().filter(AnimationActivities.Activity::available).findFirst();
if (activity.isPresent()) session.startActivity(activity.get().id());
var state = session.activityState();

AnimationActivities와 활동 시험 API는 실험 API입니다. 기존 Session 구현에는 기본 메서드가 제공되며 지원하지 않는 구현의 제어 호출은 UnsupportedOperationException으로 거부됩니다. 실제 기능의 존재를 확인하거나 대응하는 본체와 함께 사용합니다.

활동 시험은 명시적으로 시작할 때만 별도의 제어된 캐릭터 구성을 준비합니다. 일반 앱 미리보기의 자동 활동은 그대로 유지합니다. 시험 중에는 임시 캐릭터가 다른 자동 모집에 끼어들지 않습니다. 중지·완료 후에는 세션 캐릭터를 기본 대기에서 멈추며, 다음 활동 시작이나 스냅샷 교체로 다시 진행합니다. 선물 받기 후 대기·종료는 일반 자동 애니메이션 캐릭터와 동일한 유한 흐름을 사용하고, 쓰다듬기는 작성한 프레임 열을 한 번 실행한 뒤 손을 뗀 후속 동작으로 넘어갑니다. 일반 캐릭터의 반복/입력 규칙은 변경하지 않습니다. 시험이 90초 안에 끝나지 않으면 FAILED로 보고합니다.

잡힘 물리 회전 — CharacterDefinition.HeldMotion 실험

generateAutomaticAnimations(imageSet,animations,previewImage,HeldMotion)와 generateStandaloneAutomaticAnimations(imageSet,animations,previewImage,HeldMotion)에서 PHYSICS를 명시하면 해당 캐릭터만 연속 회전 잡힘을 사용합니다. LEGACY와 기존 3인자 호출은 기존 스프라이트 실행과 생성 파일 바이트를 유지합니다. null은 거부합니다. 본체 기본 Lumi, 다른 이미지셋과 다른 개체의 흔들림 상태는 변경하지 않습니다. 출력의 물리 실행 클래스와 character-profile.properties의 heldMotion=PHYSICS가 선택을 보존하므로 제작기를 종료해도 동작합니다. 이 계약을 구현한 본체가 필요하며 같은 제품 버전 문자열만으로 지원을 판단하지 마세요. 이전 본체에서 물리 출력을 레거시로 조용히 대체하지 않습니다.

피봇은 기존 잡힘 Offset=0,120과 프레임 ImageAnchor를 사용하여 이미지 좌표 ImageAnchor − (0,120)로 계산합니다. Lumi 기준점 (96,192)에서는 (96,72)입니다. 클릭한 위치 또는 그림의 불투명 영역을 새로 추정하지 않습니다. 피봇이 커서를 따라가고 기존 가상 발의 관성·감쇠 모델이 연속 회전각을 결정합니다. 빠른 마우스 이동일수록 크게 기울며 정지하면 감쇠합니다. 좌우 반전·배율도 같은 피봇을 유지합니다. 프레임 시간·순서·기준점·FRAME_ENTRY/BEHAVIOR_ENTRY·loop·음량은 그대로이며 마우스 이동이 재생 시간을 초기화하지 않습니다. 놓기·상태 이탈·제거에서 회전을 정리합니다. 공개 MascotState.bounds는 회전 후 표시 영역이고 anchor는 기존 논리 위치입니다. 표시 영역을 물리 충돌 영역으로 간주하지 마세요.

AuthoringPreview.Snapshot.forAutomaticAnimations(animations,audio,HeldMotion)는 동일 옵션을 실제 엔진에 전달하고 Snapshot.heldMotion()으로 조회합니다. 9인자 Snapshot의 마지막 인자이며 기존 8인자와 다른 생성자/팩토리는 LEGACY입니다. 자동 프로필 이외의 PHYSICS는 거부합니다. AnimationActivities.forAnimation("Pinched",registered)의 held는 Pinched 등록 시 실행할 수 있는 1인 활동입니다. Session.startActivity("held")는 대기 중인 시험 캐릭터 하나만 준비하며 사용자가 데스크톱에서 직접 집어 움직여야 합니다. 가짜 커서나 시간표를 실행하지 않습니다. 실제 잡힘 중 Pinched 단계를 보고하고 놓은 뒤 대기로 돌아오면 완료, 90초 경과 시 timed-out입니다. 일시정지·재개, 중지·교체·종료의 기존 세션 수명과 소리 정리 계약을 따릅니다. UI는 완료·실패·중지 뒤 세션을 닫아 시험 캐릭터를 제거해야 합니다.

이전 자동 출력의 읽기 전용 재구성

새 자동 캐릭터와 실제 시험은 기존 generateAutomaticAnimations(..., HeldMotion) / generateStandaloneAutomaticAnimations(..., HeldMotion) 및 AuthoringPreview.Snapshot.forAutomaticAnimations(..., HeldMotion)를 사용합니다. 미등록 활동은 자동으로 추가하지 않습니다.

CharacterDefinition.HelperVisuals와 자동 생성 함수의 5인자 오버로드는 이전 출력과의 바이트 비교·복원을 위한 호환 API입니다. LEGACY는 원래 출력, SHARED는 짧고 무음인 첫 Idle 보조 자세, SHARED_MOVEMENT는 이전 출력의 술래잡기·행렬과 그림/효과음 대체 규칙을 재현합니다. 원래 입력 프레임·순서·시간·기준점·효과음과 같은 정책을 전달해야 동일한 파일을 재구성할 수 있습니다. 반환된 파일을 별도 임시 위치에서 비교하며, 이 호출 자체가 설치된 모드나 사용자 프로젝트를 변경하지 않습니다.

이 정책은 새 제작 기능이 아니며 AnimationActivities와 AuthoringPreview.Snapshot에는 helper 정책 인수·필드를 추가하지 않습니다. 활동 조회·시험은 기존 API와 기본 실행 규칙을 유지합니다. 생성 함수의 기존 오버로드와 기본 Lumi·기존 모드의 동작은 바뀌지 않습니다.

창작마당 직접 게시

PluginContext.workshopPublisher()는 명시적으로 확인한 사용자의 현재 Steam 계정에 내보낸 모드를 게시합니다. WorkshopPublisher.account()는 EDT 밖에서 호출하며 사용 가능 여부, Steam ID, 표시 이름을 반환합니다. publish(Request, Listener)는 비동기이고 콜백도 EDT 밖입니다. UI는 계정·제목·신규/업데이트 대상·신규 공개 범위를 마지막으로 확인한 뒤 호출해야 합니다.

Request(contentDirectory, previewFile, title, description, existingItemId, expectedSteamId, clientProjectId, visibility)에서 신규 ID는 빈 문자열이고 Visibility.PUBLIC/PRIVATE를 명시합니다. 업데이트는 기존 공개 범위를 보존합니다. clientProjectId는 저장·이름 변경 뒤에도 동일해야 합니다. 본체는 파일을 검사·복사한 독립 스냅숏만 전송하고, 현재 계정을 재확인하며 업데이트 항목의 소유권을 Steam에서 확인합니다. 제목은 128 UTF-8 바이트 이하, 설명은 8000 바이트 미만, 미리보기 PNG/JPEG는 1 MiB 미만입니다.

created(itemId, ownerSteamId)는 항목 생성만 의미하며 업로드 성공이 아닙니다. 본체는 플러그인·프로젝트·계정별 저널에 ID를 전송 전에 저장하여 실패 후 재시도에서 같은 항목을 갱신합니다. 호출자도 ID를 프로젝트에 보존합니다. completed(Result)에 ID·소유자·웹 URL·약관 동의 필요 여부가 들어갑니다. failed(Failure)의 ID는 생성 후 전송 실패에서 비어 있지 않을 수 있습니다. Steam 생성 응답과 로컬 저널 기록 사이의 프로세스 강제 종료는 원자화할 수 없으므로 이 극히 짧은 구간에서 생긴 빈 항목은 Steam 페이지에서 확인해야 합니다.

close()는 이후 요청과 UI 콜백을 차단하고, 아직 제출하지 않은 작업을 중단합니다. 이미 Steam에 제출한 작업은 되돌리지 않으며 본체가 종료 결과까지 스냅숏을 유지합니다. 플러그인 컨텍스트 해제도 열린 서비스를 닫습니다. PluginTestKit에서는 Steam에 연결하지 않고 unavailable 계정을 반환합니다. 별도 창작마당 업로드나 공개는 테스트에서 자동 실행하지 않습니다.

업로드 파일 목록과 원본 수명

기존 WorkshopPublisher.Request 8인자 생성자는 일반 모드 검사 계약을 유지합니다. 파일 목록과 내용을 고정하여 게시하려면 마지막 두 인자 Map<String,String> expectedFiles, String expectedPreviewSha256를 받는 10인자 생성자를 사용합니다. expectedFiles != null이면 strict 모드이며, 사용자 확인 전에 확정한 정확한 상대 경로→소문자 SHA-256 목록과 별도 PNG/JPEG 원본 미리보기의 SHA-256이 모두 필요합니다. 상대 경로는 / 구분자를 사용하며 상위 이동·절대 경로·대소문자 충돌을 허용하지 않습니다. Map은 생성 시 방어 복사합니다.

strict 검사는 원본·SDK 사본의 실제 파일 전체를 비교합니다. 숨김 파일이나 workshop-upload.txt 같은 로컬 표식도 조용히 무시하지 않습니다. 누락·추가·내용 변경이 있으면 게시를 중단하며 변경된 파일로 확인 기준을 갱신하지 않습니다. 별도 미리보기는 1MiB 미만으로 한정해 읽고 원본 SHA-256을 확인한 뒤 PNG로 다시 인코딩합니다. 준비된 콘텐츠와 재인코딩된 미리보기는 새 항목 생성 응답 뒤를 포함해 Steam 콘텐츠 지정 직전과 제출 직전에 다시 검사합니다. 기존 일반 모드 입력의 표식 제외는 유지하되, 전송 사본에 나중에 생긴 추가 표식은 거부합니다.

Listener.sourceReleased()는 SDK가 contentDirectory·previewFile을 더 읽지 않는 시점에 정확히 한 번 EDT 밖에서 호출됩니다. 성공적인 독립 복사가 끝나면 즉시 전달되며, 준비 실패·거절·취소에도 전달됩니다. close() 뒤에도 이 자원 수명 알림은 억제하지 않으므로 호출자는 자신의 임시 배포 폴더를 이때 삭제할 수 있습니다. 이것은 업로드 성공이나 UI 갱신 알림이 아닙니다. progress/created/completed/failed의 기존 종료 후 UI 콜백 억제 규칙은 유지합니다. SDK 사본은 Steam 완료·실패까지 SDK가 소유·정리하며 로컬 모드 원본은 변경하지 않습니다. 일시적인 파일 잠금에는 한정된 삭제 재시도를 하고, 최종 정리 실패는 로컬 경고로 기록하며 원격 성공 결과를 실패로 바꾸지 않습니다.

strict SDK 사본은 소유자 전용 POSIX 권한 또는 Windows의 현재 사용자·SYSTEM ACL로 생성합니다. 파일은 기본 바이트 스트림만 복사하여 원본 ACL·속성·NTFS 대체 스트림을 전파하지 않습니다. 이는 같은 JVM에서 실행하는 승인 코드나 같은 계정의 악성 프로세스를 격리하는 샌드박스가 아니며, Steam이 이미 수락한 제출을 취소·되돌린다고 보장하지 않습니다.
