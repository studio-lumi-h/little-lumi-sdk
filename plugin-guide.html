０단계 — 아무것도 모르고 시작하기

이 절은 프로그래밍을 한 번도 해 본 적이 없는 사람을 위한 것입니다. 명령 프롬프트가 무엇인지, 「컴파일」이 무슨 말인지 몰라도 됩니다. 아래에 적힌 대로 누르고 치기만 하면 30분 안에 끝납니다. 이미 명령 프롬프트를 쓸 줄 안다면 이 절을 건너뛰고 준비물부터 보셔도 됩니다.

오늘 하게 될 일. 플러그인은 루미에 기능을 더하는 작은 프로그램입니다. 오늘은 코드를 쓰지 않습니다 — 이미 만들어져 SDK 안에 들어 있는 예제 플러그인 하나를 그대로 구워서 루미에 넣고, 루미가 뜰 때 인사하게 만듭니다. 맨 마지막에 그 인사말 한 줄만 고쳐 봅니다. 플러그인 만들기의 뼈대는 이것이 전부이고, 나머지 절은 그 한 줄이 길어지는 이야기입니다.

필요한 것. 윈도 PC, 스팀에서 산 Little LUMI Model, 인터넷. 프로그램 두 개(JDK 25 와 파이썬 3)를 새로 깝니다. 둘 다 공짜이고, 루미 말고 다른 프로그램은 건드리지 않습니다.

길잡이 아래 여덟 걸음을 순서대로 밟으세요. 걸음마다 할 일 · 됐다는 표시 · 안 되면이 붙어 있습니다. 「됐다는 표시」가 안 보이면 다음 걸음으로 넘어가지 말고 그 자리에서 「안 되면」을 읽으세요. 앞 걸음이 덜 된 채로 나아가면 나중 걸음의 오류 글이 무슨 말인지 알 수 없게 됩니다.

  1. 명령 프롬프트 여는 법

    이 가이드의 명령들은 명령 프롬프트라는 검은 창에 칩니다. 글자로 컴퓨터에 일을 시키는 창입니다.

    할 일. 키보드의 윈도 키(창문 모양)를 누르고, 바로 cmd 라고 친 다음 Enter. 검은 창이 뜹니다.

    됐다는 표시. 창 안에 C:\Users\내이름> 같은 줄이 있고 그 뒤에서 커서가 깜빡입니다. 이 줄을 프롬프트라고 부르고, 여기에 한 줄 치고 Enter 를 누르면 그 명령이 실행됩니다. 시험 삼아 아래를 쳐 보세요 — 지금 폴더 안의 파일 목록이 주르륵 나오면 창이 제대로 도는 것입니다.

    dir

    꼭 알아야 할 것 넷.

    • 폴더 옮기기는 cd. cd C:\LumiSDK 라고 치면 프롬프트 줄이 C:\LumiSDK> 로 바뀝니다. 그 뒤의 명령은 그 폴더 안에서 돕니다. 다른 드라이브로 갈 때는 D: 처럼 드라이브 글자만 먼저 치고 Enter.
    • 경로에 빈칸이 있으면 큰따옴표로 감쌉니다. cd "C:\Program Files (x86)\Steam" — 따옴표를 빼면 빈칸에서 잘려 「지정된 경로를 찾을 수 없습니다」가 납니다.
    • 붙여넣기는 마우스 오른쪽 단추. 이 페이지의 코드 상자 오른쪽 위 「복사」 단추를 누른 다음, 검은 창 안에서 마우스 오른쪽 단추를 한 번 누르면 그 자리에 붙습니다(Ctrl+V 도 됩니다). 손으로 옮겨 치지 마세요 — 오타가 실패 원인의 대부분입니다.
    • 창을 닫을 때는 exit 를 치거나 창 오른쪽 위 X 를 누릅니다. 창을 닫아도 하던 일은 남습니다.

    안 되면. 윈도 키를 눌러도 아무 칸이 안 뜨면 화면 아래 시작 단추를 마우스로 누르고 명령 프롬프트 라고 치세요. 창은 떴는데 명령마다 「내부 또는 외부 명령…」이 나오는 것은 아직 정상입니다 — 아무것도 안 깔았기 때문입니다. 다음 걸음에서 깝니다.

  2. JDK 25 설치 — 자바 코드를 굽는 도구

    플러그인은 자바로 만듭니다. 사람이 읽는 자바 코드를 컴퓨터가 읽는 jar 파일로 바꾸는 것을 굽는다(컴파일)고 하고, 그 도구가 JDK 입니다. 루미 안에도 자바가 들어 있지만 그것은 실행 전용이라 굽지는 못합니다.

    할 일. adoptium.net 에 들어가 Temurin 25 · Windows · x64 · JDK · .msi 를 고르고 내려받습니다(JRE 가 아니라 JDK 입니다). 받은 파일을 두 번 눌러 설치합니다. 「Next」를 누르다 보면 나오는 Custom Setup 화면에서 「Set JAVA_HOME variable」과 「Add to PATH」 두 줄의 아이콘을 눌러 「Will be installed on local hard drive」로 바꾸세요. 기본값이 꺼짐(X 표시)이라 그냥 넘기면 나중에 명령이 안 먹습니다.

    됐다는 표시. 설치가 끝나면 명령 프롬프트를 닫고 새로 여세요(새 창부터 설정이 먹습니다). 그리고 아래를 칩니다.

    javac -version
    이렇게 나오면 성공 (뒷자리 숫자는 달라도 됩니다)javac 25.0.4

    안 되면. 「'javac'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램…이 아닙니다」가 나오는 경우는 셋입니다. ① 명령 프롬프트를 새로 안 열었습니다 — 창을 닫고 다시 여세요. ② 설치할 때 위 두 항목을 안 켰습니다 — 받아 둔 .msi 를 다시 실행해 Change 를 고르고 두 항목을 켜세요. ③ JDK 가 아니라 JRE 를 받았습니다 — 다시 받으세요. 숫자가 javac 21 처럼 25보다 작게 나오면 예전 자바가 먼저 잡힌 것이니 25를 설치한 뒤 다시 확인하세요.

  3. 파이썬 3 설치 — 굽기를 대신 해 주는 도구

    SDK 의 굽기 도구(build_plugin.py)와 시험 도구(run_tests.py)가 파이썬으로 되어 있습니다. 파이썬 코드를 쓸 일은 없고, 그 도구를 돌리기 위해서만 필요합니다.

    할 일. python.org/downloads 에서 노란 「Download Python 3.x」 단추를 눌러 받습니다. 받은 파일을 두 번 누르면 첫 화면 맨 아래에 「Add python.exe to PATH」 체크 칸이 있습니다. 이것을 꼭 켜고 「Install Now」를 누르세요.

    됐다는 표시. 다시 명령 프롬프트를 닫고 새로 연 다음 아래를 칩니다.

    python --version
    이렇게 나오면 성공Python 3.13.5

    안 되면. 마이크로소프트 스토어 창이 뜨거나 「Python was not found」가 나오면 아직 안 깔린 것입니다. 윈도에는 파이썬을 깔기 전에도 python 이라는 이름의 스토어를 여는 껍데기가 있기 때문입니다. 위 설치를 다시 하되 「Add python.exe to PATH」를 켜세요. 설치를 분명히 했는데도 스토어가 뜬다면 설정 → 앱 → 고급 앱 설정 → 앱 실행 별칭에서 python.exe 와 python3.exe 를 끄고 명령 프롬프트를 새로 여세요.

  4. 모드 SDK 받아 풀기

    플러그인을 굽는 데 필요한 것이 모두 든 zip 파일입니다.

    할 일. Little LUMI SDK 다운로드에서 내가 쓰는 루미와 같은 버전의 릴리스를 고르고, Assets 아래의 LittleLUMI-ModSDK-1.5.1-…zip 을 받습니다(이 가이드 기준 앱과 SDK 는 1.5.1 입니다). 탐색기에서 그 zip 을 오른쪽 단추 → 압축 풀기. 푸는 자리는 한글과 빈칸이 없는 짧은 경로가 편합니다 — 아래에서는 C:\LumiSDK 를 쓰겠습니다.

    다 풀면 C:\LumiSDK 바로 아래가 이렇게 생겼습니다.

    C:\LumiSDK\ ├─ lib\ ← 굽기에만 쓰는 루미 jar. 이것으로 루미를 실행할 수는 없습니다 ├─ tools\ ← build_plugin.py(굽기) · run_tests.py(앱 없이 시험) · pack_workshop.py(창작마당에 올리기 전 검사) ├─ docs\ ← API.md(할 수 있는 것) · CATALOG.md(이름표 모음) · CHANGELOG.md ├─ examples\hello\ ← 오늘 쓸 예제 플러그인 ├─ examples\plugin-transformer\ ← 고급 예제. 오늘은 안 씁니다 ├─ plugin-guide.html ← 이 문서 ├─ README.md ← 한 장짜리 요약 ├─ LICENSE-SDK.txt ← 쓰는 조건 └─ sdk.json ← 이 SDK 의 버전 정보

    됐다는 표시. 명령 프롬프트에서 아래 두 줄을 차례로 칩니다. 위 이름들이 목록에 보이면 됩니다.

    cd C:\LumiSDK
dir

    안 되면. 목록에 lib · tools 대신 LittleLUMI-ModSDK-… 폴더 하나만 보이면 한 겹 더 들어간 것입니다. 그 폴더 안의 것들을 C:\LumiSDK 로 끌어올리거나, 앞으로 cd 할 자리를 그 폴더로 잡으세요. lib\Shimeji-ee.jar 이 없으면 zip 이 덜 풀린 것이니 다시 푸세요.

  5. 예제 굽기 — 첫 명령

    드디어 굽습니다. 예제 폴더 examples\hello 를 도구에 건네주기만 하면 됩니다.

    할 일. 명령 프롬프트에서 아래 두 줄.

    cd C:\LumiSDK
python tools\build_plugin.py examples\hello

    됐다는 표시. 몇 초 뒤 built: 로 시작하는 줄이 나옵니다. 이 줄에 적힌 자리에 jar 파일이 만들어진 것입니다(괄호 안 숫자는 버전에 따라 다를 수 있습니다).

    이렇게 나오면 성공built: C:\LumiSDK\dist\hello.lumi.sample\plugins\hello.lumi.sample.jar  (hello.lumi.sample, 2 source(s), 4 resource(s))
done: copy C:\LumiSDK\dist\hello.lumi.sample into the game as mods\<name> and restart

    안 되면. javac not found 은 2번 걸음이 덜 된 것입니다 — javac -version 부터 다시 확인하거나, 아래처럼 자리를 직접 알려 주세요.

    python tools\build_plugin.py examples\hello --javac "C:\Program Files\Eclipse Adoptium\jdk-25.0.4.7-hotspot\bin\javac.exe"

    스토어 창이 뜨면 3번 걸음이 덜 된 것입니다. plugin.json missing: … 은 폴더 이름을 잘못 적은 것이니 examples\hello 철자를 확인하세요. can't open file …build_plugin.py 는 C:\LumiSDK 가 아닌 곳에서 친 것이니 cd 부터 다시 하세요.

  6. 루미에 넣고 확인하기

    구운 jar 를 루미 폴더의 mods\ 에 넣으면 설치입니다. 별도 설치 프로그램은 없지만, 복사한 코드 모드는 앱에서 직접 활성화해야 실행됩니다.

    할 일 ① 루미 끄기. 화면 오른쪽 아래 시계 옆의 ^ 를 눌러 트레이를 펼치고 루미 아이콘을 오른쪽 단추로 눌러 종료. 루미가 켜져 있으면 파일이 잠겨 복사가 막힙니다.

    할 일 ② 루미 폴더 열기. 스팀 라이브러리에서 Little LUMI Model 을 오른쪽 단추 → 관리 → 로컬 파일 보기. mods\ 폴더가 보이는 그 창입니다.

    할 일 ③ 복사. 탐색기 창을 하나 더 열어 C:\LumiSDK\dist 로 갑니다. 그 안의 hello.lumi.sample 폴더를 통째로 루미 폴더의 mods\ 안으로 끌어다 놓습니다. 결과는 이 모양이어야 합니다.

    <루미 폴더>\mods\ └─ hello.lumi.sample\ └─ plugins\ └─ hello.lumi.sample.jar

    할 일 ④ 활성화. 스팀에서 루미를 켭니다. 시작 안내의 확인은 설정 > 모드로 이동할 뿐, 모드를 활성화하지 않습니다. hello.lumi.sample 앞의 빨간 비활성화 칩을 확인하고 토글을 누르세요. 출처와 권한 안내를 읽고 신뢰할 수 있는 예제인지 확인한 뒤 활성화를 누릅니다. 이 실행에서는 아직 인사와 설정 카드가 나타나지 않습니다.

    할 일 ⑤ 다시 실행. 트레이에서 루미를 완전히 종료한 뒤 스팀에서 다시 켭니다. 활성화한 코드와 데이터는 이 다음 실행부터 적용됩니다.

    됐다는 표시. 활성화 후 다시 실행하면 아래 내용을 확인할 수 있습니다.

    • 루미가 뜨고 잠시 뒤 말풍선에 「루바! (플러그인)」. 앱 언어가 영어면 「Luba! (plugin)」입니다.
    • 인사를 놓쳤으면 트레이의 루미 아이콘을 오른쪽 단추로 눌러 보세요. 「Hello LUMI: 인사하기」 줄이 새로 생겨 있고, 누르면 루미가 한 마디 합니다.
    • 트레이 → 설정 → 「모드」 탭에 hello.lumi.sample 줄과 「플러그인」 칩이 보입니다. 그 줄의 「자세히」를 누르면 예제가 선언해 둔 설정 칸 둘(「시작할 때 인사하기」·「인사 말투」)이 루미 화면 안에 그려져 있습니다.

    설정과 트레이 확인. 「시작할 때 인사하기」는 다음 시작의 인사를 켜고 끕니다. 「인사 말투」를 「차분하게」 또는 「신나게」로 고른 뒤 트레이의 「Hello LUMI: 인사하기」를 누르면 각각 「트레이에서 인사해요.」 또는 「트레이에서 인사해요!!!」가 나옵니다. 인사 말투는 시작 인사 문구를 바꾸지 않습니다.

    안 되면. 빨간 「비활성화」 칩이 남아 있으면 활성화 절차를 확인하세요. 「다음 실행 시 적용」이면 앱을 완전히 종료하고 다시 켜세요. 「모드」 탭에 줄이 아예 없으면 jar 를 mods\ 바로 아래에 놓은 것입니다 — 줄은 mods\ 아래의 폴더마다 하나씩 생기고 낱개 파일은 무시됩니다. 줄은 있는데 「플러그인」 대신 「파일」 칩이 붙어 있으면 폴더 깊이가 틀린 것이니 jar 가 mods\hello.lumi.sample\plugins\ 안에 있는지 보세요. 줄은 있는데 「불러오지 못했어요」가 붙어 있으면 <루미 폴더>\app\LittleLumiLog0.log.0 을 메모장으로 열어 Plugin 이 든 줄을 찾으세요. 증상별 표는 안 될 때에 있습니다.

  7. 한 줄 고쳐 보기

    이제 인사말을 내 것으로 바꿔 봅니다. 자바 코드가 아니라 문구 파일 한 줄만 고칩니다.

    할 일 ①. C:\LumiSDK\examples\hello\src\plugin_ko.properties 를 메모장이나 VS Code 로 엽니다. 이런 줄이 있습니다.

    examples\hello\src\plugin_ko.propertiesgreeting=루바! (플러그인)

    = 오른쪽만 원하는 말로 바꾸고 UTF-8 로 저장합니다(메모장은 저장 창 아래 「인코딩」에서 UTF-8 을 고릅니다).

    고친 뒤greeting=내가 고친 인사입니다

    할 일 ②. 루미를 종료합니다. 실행 중이면 jar 가 잠겨 덮어쓰기가 거부됩니다 — 이것을 잊는 것이 「고쳤는데 그대로다」의 가장 흔한 원인입니다.

    할 일 ③. 다시 굽고, 새 jar 를 아까 그 자리에 덮어씁니다.

    cd C:\LumiSDK
python tools\build_plugin.py examples\hello

    C:\LumiSDK\dist\hello.lumi.sample\plugins\hello.lumi.sample.jar 을 <루미 폴더>\mods\hello.lumi.sample\plugins\ 로 복사하고 「덮어쓰기」를 고릅니다. 매번 복사하기 귀찮으면 굽기 명령에 --out 을 붙여 바로 그 자리에 굽게 할 수 있습니다.

    python tools\build_plugin.py examples\hello --out "<루미 폴더>\mods\hello.lumi.sample\plugins"

    할 일 ④ 재활성화. 루미를 켜고 설정 > 모드에서 hello.lumi.sample을 다시 활성화합니다. 문구 한 줄만 고쳐도 JAR 내용이 달라지므로 이전 허용을 그대로 사용하지 않습니다. 권한 안내를 확인하고 활성화를 누른 뒤, 루미를 완전히 종료하고 다시 켭니다. 의존 라이브러리 JAR이 바뀌었을 때도 같은 절차가 필요합니다.

    됐다는 표시. 「시작할 때 인사하기」가 켜져 있고 앱 언어가 한국어이면 시작 말풍선에 새로 적은 문구가 뜹니다. 트레이 인사는 별도 문구이므로 이 한 줄 수정으로 바뀌지 않습니다.

    안 되면. 옛 문구가 그대로면 ① 루미를 안 끄고 덮어써서 복사가 조용히 실패했거나 ② 굽기 전에 파일을 저장하지 않았거나 ③ 다른 폴더에 복사한 것입니다. 글자가 ??? 나 깨진 기호로 나오면 UTF-8 로 저장하지 않은 것이니 다시 저장하고 다시 구우세요.

  8. 여기까지 됐으면 다음은

    축하합니다. 굽고 · 넣고 · 고치는 고리를 한 바퀴 돌았습니다. 앞으로 만들 플러그인이 아무리 커져도 이 고리는 똑같습니다. 다음 순서로 읽으세요.

    • 플러그인이 뭔가요 — 방금 한 일이 무엇이었는지.
    • 첫 플러그인 만들기 — 예제가 아니라 내 폴더를 처음부터 만들기. 빠른 길은 examples\hello 폴더를 통째로 복사해 my-plugin 으로 이름을 바꾸고, 그 안 plugin.json 의 id 와 name 을 내 것으로 고친 뒤 python tools\build_plugin.py my-plugin 을 치는 것입니다.
    • 할 수 있는 것 · 예제 모음 — 말시키기·행동시키기·타이머·메뉴·설정 칸.
    • 훅으로 판정 바꾸기 · 데이터 모드는 조각으로 — 루미의 판정과 데이터를 건드리기.
    • 나눠 주기 — 다 됐으면 창작마당에 올리기.
    • 안 될 때 · 용어 사전 — 막힐 때마다.

AI 도구로 만들기

자바를 몰라도 클로드 코드나 코덱스 같은 코딩 보조 AI 에게 시켜서 플러그인을 만들 수 있습니다. 다만 분명히 해 둘 것이 하나 있습니다. 코드는 AI 가 쓰지만, 그것을 남에게 내보내는 책임은 사람에게 있습니다. 플러그인은 루미와 같은 프로그램 안에서 여러분 계정 권한으로 돌고, 받는 사람은 여러분을 믿고 설치합니다. 이해하지 못한 코드는 내보내지 마세요.

AI 에게 시키더라도 위 ０단계의 2·3·4번 걸음(JDK 25 · 파이썬 3 · SDK 풀기)은 사람이 먼저 해 두어야 합니다. AI 는 대개 그 도구를 대신 깔아 주지 않습니다.

무엇을 건네주나

  • 폴더를 통째로 볼 수 있는 도구(명령 프롬프트에서 도는 종류)라면 C:\LumiSDK 를 작업 폴더로 열어 주는 것이 가장 좋습니다. 그러면 AI 가 문서와 예제를 직접 읽고, 굽기와 시험 명령까지 스스로 돌려 봅니다.
  • 글만 붙여 넣는 도구라면 이 넷을 넣어 주세요. docs\API.md(할 수 있는 것 전부) · docs\CATALOG.md(행동·이벤트·훅·설정 키 이름표) · examples\hello\plugin.json · examples\hello\src\hello\HelloPlugin.java. 문서가 길어 다 못 넣겠으면 docs\API.md 만이라도 꼭 넣으세요 — 그것이 없으면 AI 가 없는 메서드를 지어냅니다.

붙여 넣을 첫 지시문

아래를 그대로 복사해 <여기에…> 부분만 내 말로 바꿔 넣으세요. 적어 둔 제약들은 실제로 자주 어긋나는 것만 고른 것입니다.

AI 에게 줄 첫 지시문리틀 루미(Little LUMI Model)용 플러그인을 만들려고 합니다. 작업 폴더는 이 모드 SDK 폴더입니다.

먼저 docs\API.md 와 docs\CATALOG.md 를 읽고, examples\hello 를 본보기로 삼으세요.

만들 것: <여기에 하고 싶은 일을 한두 문장으로. 예: 30분마다 루미가 스트레칭하자고 말하고,
집중 모드가 켜져 있는 동안에는 조용히 있게 하기>

지켜야 할 것:
- JDK 25 로 컴파일됩니다. 자바 25 문법까지 써도 됩니다.
- 새 폴더 my-plugin 을 만들고 examples\hello 와 같은 구조로 두세요.
  plugin.json(폴더 맨 위) / src\<패키지>\*.java /
  src\META-INF\services\com.group_finity.mascot.lumi.plugin.LumiPlugin
- 그 services 파일에는 진입 클래스의 전체 이름을 한 줄로 적습니다(예: my.plugin.MyPlugin).
  plugin.json 의 id 를 적는 파일이 아닙니다.
- plugin.json 의 id 는 소문자·숫자·마침표·하이픈·밑줄만 쓰고 첫 글자는 소문자나 숫자입니다.
  api_version 은 1, app_version 은 1.5.1 으로 적으세요. id 는 데이터 폴더 이름이 되므로 나중에 바꾸지 않습니다.
- 앱 기능은 PluginContext(ctx)를 통해서만 부르세요. docs\API.md 에 없는 앱 클래스를 직접 부르거나
  리플렉션으로 뒤지지 마세요.
- 앱의 판정을 바꿔야 하면 ctx.hook(...) 으로 답하세요. 바이트코드 변환(ctx.patch · ctx.onLoad ·
  LumiTransformer)은 쓰지 마세요.
- 사용자가 직접 건 약속(알람, 눌러서 부른 말)은 막지 마세요.
- 내 설정 값은 ctx.prefs() 에 두세요. 비밀번호나 API 키는 저장하지 마세요.
  인터넷을 쓰면 plugin.json 의 network 를 true 로 적으세요.
- test\*.java 에 PluginTestKit 를 쓰는 검사를 하나 이상 넣으세요.
- 빌드는 python tools\build_plugin.py my-plugin, 검사는 python tools\run_tests.py my-plugin 입니다.
  두 명령이 모두 통과할 때까지 고치세요.
- 지어내지 마세요. docs\API.md 와 docs\CATALOG.md 에 있는 메서드·이벤트 토픽·훅 이름·행동 이름만 쓰고,
  필요한 것이 문서에 없으면 없다고 말하세요.

사람이 직접 해야 하는 확인

AI 가 「다 됐습니다」라고 말해도 그것은 확인이 아닙니다. 아래 다섯은 여러분 손으로 하세요.

  1. 굽기가 된다. python tools\build_plugin.py my-plugin 이 built: … 줄로 끝나야 합니다. 오류 글이 섞여 있으면 아직 안 된 것입니다.
  2. 시험이 통과한다. python tools\run_tests.py my-plugin 이 OK: N test class(es) passed 로 끝나야 합니다. FAILED: 가 보이면 그 줄을 그대로 AI 에게 돌려주세요.
  3. 앱에서 실제로 동작한다. 루미를 끄고, jar 를 mods\<이름>\plugins\ 에 넣고, 다시 켜서 눈으로 확인하세요. AI 는 루미를 띄워 볼 수 없으니 이 걸음만은 대신해 주지 못합니다.
  4. 로그가 깨끗하다. <루미 폴더>\app\LittleLumiLog0.log.0 을 열어 내 id 를 찾으세요. Plugin loaded: <내 id> 가 있고, start() failed 나 내 id 가 든 경고 줄이 없어야 합니다.
  5. 코드를 한 번 읽는다. 파일을 지우거나 밖으로 보내는 코드가 없는지, plugin.json 의 network 와 affects_character 가 실제 동작과 맞는지 보세요. 남의 플러그인 폴더(plugindata\<남의 id>\)를 읽는 코드가 있으면 지우세요. 판단이 서지 않으면 규칙과 주의를 읽고 그 잣대로 보세요.
주의 AI 는 없는 메서드와 없는 훅 이름을 그럴듯하게 지어냅니다. 코드에 처음 보는 ctx. 호출이 있으면 docs\API.md 에서 그 이름을 찾아보세요. 없으면 굽기에서 걸리거나, 더 나쁘게는 구워지기는 해도 앱에서 아무 일도 일어나지 않습니다.

플러그인이 뭔가요

리틀 루미의 모드는 두 가지입니다.

  • 데이터 모드 — 그림·대사·행동 설정 파일을 바꾸는 것. 코드가 필요 없고, mods\ 폴더에 파일을 넣으면 끝입니다. 방법은 설치 폴더의 mods\Mods Guide.txt에 있습니다.
  • 플러그인 — 작은 프로그램(Java 코드)을 루미 안에서 돌리는 것. 이 페이지가 다루는 것이 이것입니다. 루미에게 말을 시키고, 행동을 시키고, 루미가 무엇을 하는지 듣고, 타이머를 돌리고, 파일을 읽고 쓸 수 있습니다. 루미 앱이 할 수 있는 것은 거의 다 할 수 있습니다.

플러그인 하나는 jar 파일 하나입니다. 그 안에 여러분이 쓴 코드와, 「이 플러그인은 누구고 뭘 하는가」를 적은 plugin.json이 들어 있습니다. 루미는 시작할 때 plugins\ 폴더의 jar를 전부 읽어 들이고, 옵션 창의 「모드」 탭에 무엇이 실렸는지 보여 줍니다.

흐름 폴더 만들기 → 파일 셋 쓰기 → 명령 두 줄로 굽기 → mods\에 넣기 → 루미 실행. 그것이 전부입니다.

준비물

  1. JDK 25 설치

    Java 코드를 jar로 구우려면 JDK(Java Development Kit)가 필요합니다. 루미에 들어 있는 것은 실행 전용(JRE)이라 굽기는 못 합니다. adoptium.net에서 Temurin 25 (Windows x64, .msi)를 받아 설치하세요. 설치 화면에서 「Set JAVA_HOME」과 「Add to PATH」를 켜 두면 편합니다.

    설치가 됐는지 확인: 시작 메뉴에서 명령 프롬프트를 열고 아래를 치세요.

    javac -version

    javac 25.x.x처럼 나오면 준비 끝. 「내부 또는 외부 명령이 아닙니다」가 나오면 PATH 옵션을 안 켠 것입니다. 다시 설치하거나 명령 프롬프트를 새로 여세요.

  2. 파이썬 3 설치

    SDK 의 굽기 도구(build_plugin.py)와 시험 도구(run_tests.py)가 파이썬으로 되어 있습니다. python.org에서 Python 3 를 받아 설치하고, 설치 첫 화면의 「Add python.exe to PATH」를 꼭 켜세요.

    확인: 명령 프롬프트를 새로 열고 아래를 치세요.

    python --version

    Python 3.x.x처럼 나오면 준비 끝. 윈도에는 파이썬을 깔기 전에도 python이라는 명령이 있는데, 그것은 Microsoft Store 를 여는 껍데기입니다 — 스토어 창이 뜨거나 「Python was not found」가 나오면 아직 설치가 안 된 것입니다.

  3. 모드 SDK 받기

    플러그인은 모드 SDK 로 굽습니다 — 컴파일용 루미 jar, 굽기 도구, 예제, API 문서가 zip 하나에 들어 있습니다(모드 SDK 절). 받아서 아무 데나 푸세요. 예: C:\LumiSDK. 아래에서 <SDK 폴더>라고 부르겠습니다.

  4. 글 편집기

    메모장도 되지만 VS Code(무료)를 권합니다. 파일을 UTF-8로 저장해 주고 Java 문법에 색을 입혀 줍니다. 메모장을 쓴다면 저장할 때 인코딩을 UTF-8로 고르세요.

  5. 루미 설치 폴더 찾기

    스팀 라이브러리에서 Little LUMI Model을 우클릭 → 관리 → 로컬 파일 보기. 열리는 폴더가 이렇게 생겼습니다.

    Little LUMI Model\ ├─ Little LUMI.exe ← 실행 파일 ├─ mods\ ← 모드와 플러그인을 넣는 곳 │ └─ Mods Guide.txt └─ app\ ← 루미 본체 ├─ Shimeji-ee.jar ← 루미 본체 jar (SDK 의 lib\ 에 같은 것이 들어 있습니다) ├─ lib\ ← 루미가 쓰는 라이브러리 ├─ plugindata\ ← 플러그인마다 제 데이터 폴더 (plugindata\<id>\). 모드의 jar 는 mods\ 에서 바로 읽습니다 └─ LittleLumiLog0.log.0 ← 로그. 안 될 때 여기부터

    이 폴더의 주소를 복사해 두세요. 아래에서 <루미 폴더>라고 부르겠습니다. 예: C:\Program Files (x86)\Steam\steamapps\common\Little LUMI Model

첫 플러그인 만들기

루미가 뜨면 「안녕! 첫 플러그인이야」라고 말하고, 루미를 더블클릭하면 두 마디를 차례로 하고, 루미가 행동을 바꿀 때마다 로그에 적는 플러그인입니다. 파일 셋을 만들고 명령 한 줄을 치면 됩니다.

  1. 폴더 만들기

    아무 데나 좋습니다. 예를 들어 C:\LumiPlugins\hello. 그 안에 이 모양으로 폴더와 파일을 만듭니다.

    C:\LumiPlugins\hello\ ├─ plugin.json ← 이름표 (플러그인 폴더 맨 위) └─ src\ ├─ hello\ │ └─ HelloPlugin.java ← 코드 └─ META-INF\ └─ services\ └─ com.group_finity.mascot.lumi.plugin.LumiPlugin ← 확장자 없는 파일. 진입점 이름

    SDK 의 examples\hello\가 딱 이 모양입니다. 그 폴더를 통째로 복사해 이름만 바꿔 시작해도 됩니다.

    주의 마지막 파일은 확장자가 없습니다. 메모장으로 저장할 때 「파일 이름」에 큰따옴표로 감싸 "com.group_finity.mascot.lumi.plugin.LumiPlugin"이라고 적으면 .txt가 안 붙습니다. 윈도 탐색기에서 「파일 확장명 보기」를 켜 두면 확인하기 쉽습니다.

  2. plugin.json — 이름표

    플러그인 폴더 맨 위의 plugin.json에 이렇게 적습니다. id는 세상에 하나뿐인 이름이어야 하니 내 별명.플러그인이름처럼 짓습니다. 소문자·숫자·점·하이픈·밑줄만 됩니다.

    plugin.json{
  "id": "mynick.hello",
  "name": "Hello LUMI",
  "version": "1.0.0",
  "author": "내 별명",
  "description": "루미가 뜨면 인사하고, 행동이 바뀔 때마다 로그에 적어요.",
  "dependencies": [],
  "api_version": 1,
  "app_version": "1.5.1",
  "affects_character": false,
  "network": false
}
    항목뜻
    id고유 이름. 데이터 폴더 이름과 jar 이름으로도 쓰입니다. 나중에 바꾸면 다른 플러그인으로 취급되니 처음에 잘 정하세요.
    name · version · author · description「모드」 탭에 그대로 보입니다. 버전은 1.0.0 꼴.
    dependencies먼저 실려야 하는 다른 플러그인의 id 목록. 그것이 안 실려 있으면 내 플러그인은 실리지 않고 탭에 「다른 플러그인이 필요해요」로 표시됩니다.
    api_version이 가이드 기준 1.
    app_version동작을 확인한 앱 버전. 지금 앱과 다르면 「모드」 탭에 「1.5.1용」 같은 칩이 붙습니다 — 알림일 뿐 막지 않습니다.
    affects_character루미의 행동이나 대사를 바꾸면 true. 탭에 「행동을 바꿈」 표시가 붙습니다.
    network인터넷을 쓰면 true. 탭에 「인터넷 사용」 표시가 붙습니다. 사용자에게 솔직하게 알리는 용도입니다.

  3. HelloPlugin.java — 코드

    src\hello\HelloPlugin.java. 처음 보는 낱말이 있어도 그대로 베끼세요. 뜻은 아래 할 수 있는 것에서 하나씩 풉니다.

    src\hello\HelloPlugin.javapackage hello;

import com.group_finity.mascot.lumi.plugin.LumiPlugin;
import com.group_finity.mascot.lumi.plugin.PluginContext;

public final class HelloPlugin implements LumiPlugin {

    @Override
    public void start(PluginContext ctx) {
        // 루미와 엔진이 다 뜬 뒤에 "ready" 가 한 번 옵니다. 그때 인사합니다.
        ctx.on("ready", event -> ctx.say("안녕! 첫 플러그인이야", 4000));

        // 루미를 더블클릭하면 두 마디를 차례로 합니다. sayQueued 는 앞 말이 끝난 뒤에 다음 말을 띄웁니다.
        ctx.on("doubleclick", event -> {
            ctx.sayQueued("불렀어요?", 2500);
            ctx.sayQueued("여기 있어요!", 2500);
        });

        // 루미가 행동을 바꿀 때마다 옵니다. 로그 파일에 한 줄씩 남깁니다.
        ctx.on("behavior", event ->
                ctx.log().info(event.get("imageSet") + " 가 " + event.get("name") + " 을(를) 시작했어요"));
    }

    @Override
    public void stop() {
        // 루미가 꺼질 때 불립니다. 정리할 것이 있으면 여기에.
    }
}

  5. 굽기 — 명령 한 줄

    명령 프롬프트를 열고 <SDK 폴더>로 가서 한 줄을 치세요. SDK 의 lib\에 대고 컴파일하고, plugin.json과 진입점 파일까지 넣어 jar 로 묶어 줍니다.

python tools\build_plugin.py C:\LumiPlugins\hello

    built: …\dist\mynick.hello\plugins\mynick.hello.jar 줄이 나오면 성공입니다. jar 이름은 plugin.json의 id를 따릅니다. 빨간 글씨가 나오면 안 될 때를 보세요.

    팁 --out으로 바로 루미 폴더에 넣을 수 있습니다: python tools\build_plugin.py C:\LumiPlugins\hello --out "<루미 폴더>\mods\hello\plugins". javac가 PATH 에 없으면 --javac "C:\Program Files\Eclipse Adoptium\jdk-25…\bin\javac.exe"처럼 자리를 알려 주세요. 매번 치기 귀찮으면 이 줄을 build.bat로 저장해 두고 더블클릭하세요.
    도구 없이 손으로 굽기

    JDK 의 javac와 jar만으로도 됩니다. 플러그인 폴더에서, <루미 폴더>를 여러분 것으로 바꿔 두 줄:

    javac --release 25 -encoding UTF-8 -cp "<루미 폴더>\app\Shimeji-ee.jar;<루미 폴더>\app\lib\*" -d out src\hello\HelloPlugin.java
jar --create --file mynick.hello.jar -C out . plugin.json -C src META-INF

    SDK 대신 설치 폴더의 jar 에 대고 컴파일하는 것뿐, 나오는 jar 는 같습니다.

  6. 설치하기

    루미 폴더의 mods\ 아래에 내 모드 폴더를 만들고, 그 안의 plugins\에 jar를 넣습니다. 굽기에서 --out을 썼다면 이미 거기 있습니다.

    <루미 폴더>\mods\ └─ hello\ └─ plugins\ └─ mynick.hello.jar

    루미는 시작할 때마다 mods\의 폴더를 app\ 위에 얹습니다(그림·설정 같은 데이터). plugins\의 jar는 복사하지 않고 모드 폴더에서 바로 읽습니다. 스팀이 파일을 검증해 되돌려도 다음 실행에 다시 얹히니 신경 쓰지 않아도 됩니다.

  7. 실행하고 확인하기

    루미가 이미 떠 있으면 트레이에서 종료하고 다시 실행하세요(플러그인은 시작할 때만 읽습니다). 설정 > 모드에서 새 모드의 토글을 누르고 권한 안내를 확인한 뒤 「활성화」를 선택하세요. 시작 안내의 「확인」만으로는 활성화되지 않습니다. 앱을 완전히 종료하고 다시 켠 뒤 말풍선에 「안녕! 첫 플러그인이야」가 나오면 성공! 루미를 빠르게 두 번 누르면 「불렀어요?」 「여기 있어요!」가 이어서 나옵니다.

    확인할 곳 둘:

    • 트레이 우클릭 → 설정 → 「모드」 탭. 내 모드 카드가 보입니다. 「자세히」를 누르면 플러그인 상태가 나오고, 문제가 있으면 거기에 이유가 적힙니다.
    • <루미 폴더>\app\LittleLumiLog0.log.0. 메모장으로 열어 Plugin loaded: mynick.hello를 찾아 보세요. 루미를 클릭해 행동을 바꾸면 여러분이 적은 로그 줄도 쌓입니다.

할 수 있는 것

start()에서 받는 ctx(PluginContext)가 루미로 통하는 문입니다. 이 절의 표는 안정 항목과 실험 항목을 구분하지 않습니다 — 아래에 적힌 문 가운데 상당수가 아직 「실험」이라 같은 api_version 안에서도 바뀌거나 없어질 수 있습니다. 어느 것이 안정이고 어느 것이 실험인지는 docs\API.md 의 표(이름 뒤의 「실험」 칩)와 §8 「호환 정책」에서 확인하세요. 전체 목록과 정확한 인자는 모드 SDK의 docs\API.md §3, 이름표(행동·이벤트·훅·설정 키)는 docs\CATALOG.md에 있습니다.

말하기

부르는 법하는 일
ctx.say("말", 4000)마지막으로 말한 캐릭터의 말풍선에 글을 띄웁니다. 둘째 숫자는 밀리초(4000 = 4초, 0 이하면 기본 길이). 이미 떠 있는 말은 바로 덮습니다.
ctx.sayFor("Lumi", "말", 4000)특정 캐릭터(이미지셋 폴더 이름)에게 말시킵니다.
ctx.sayQueued("말", 3000) · ctx.sayQueuedFor("Lumi", "말", 3000)줄 세우기. 지금 말이 내려간 뒤 차례로 나옵니다(최대 20줄). 포모도로 안내처럼 순서가 있는 말은 이것으로. ctx.clearQueue()는 내 줄을 비우고, ctx.queueLength()는 전체 대기 수.
ctx.ask("물음", List.of("가위", "바위", "보"), 10000, i -> …) · ctx.askFor("Lumi", …)선택지 말풍선. 물음 아래에 단추 2~4개가 붙습니다. 사용자가 고르면 i에 번호(0부터)가 옵니다. -1은 떴는데 답이 없었다는 뜻(시간 초과·Esc·캐릭터가 사라짐), -2는 앱이 거두었다는 뜻 — 이미 뜬 물음도 거둘 수 있습니다(내가 새 ask를 불러 대체됨 · clearQueue() · 줄에서 너무 오래 기다림 · 줄이 참). 말풍선은 한 번에 하나만 뜨고 다른 플러그인의 물음은 줄을 섭니다 — 내 새 물음은 내 옛 물음만 갈아치우고 남의 것은 밀지 않습니다. 시간 제한(셋째 인자)은 뜬 순간부터 세고, 줄에서 기다릴 최대 시간은 콜백 앞의 넷째 인자로 줍니다(ctx.ask("물음", 보기, 10000, 5000, i -> …), 안 주면 30초). 답은 choice 이벤트로도 나갑니다.
ctx.hideBubble() · ctx.showBusy("Lumi")말풍선 내리기 · 「···」 생각 중 표시(다음 말이 덮습니다).

부르는 법하는 일
ctx.every(처음, 주기, () -> …) · ctx.after(ms, () -> …)타이머. 루미가 쥔 스레드에서 돌고, 앱이 끝날 때 알아서 끊습니다 — Timer를 만들 필요가 없습니다. 돌아오는 ScheduledHandle의 cancel()로 멈춥니다. 예외가 나도 다음 회차는 계속 돕니다.
ctx.onEdt(() -> …) · ctx.offEdt(() -> …)창·메뉴를 만질 때는 onEdt(Swing 스레드), 오래 걸리는 일은 offEdt(내 플러그인 스레드).
정리는 루미가 stop()이 끝나면 컨텍스트로 등록한 이벤트 리스너·훅·단축키·메뉴 줄·타이머를 루미가 한꺼번에 거둡니다. 파일 핸들, 직접 만든 작업 스레드, prefs().onChange 리스너는 루미가 모르니 stop()에서 직접 닫으세요.

python tools\run_tests.py my-plugin모드 SDK의 도구. 내 플러그인 폴더의 test\*.java를 굽고 하나씩 돌립니다. 예제는 SDK의 examples\hello\test\.

규칙과 주의

  • 플러그인은 루미와 같은 프로그램 안에서, 여러분 계정 권한으로 돕니다. 여러분이 할 수 있는 것은 다 할 수 있습니다. 그만큼 사용자는 여러분을 믿고 설치하는 것입니다. 사용자 파일을 함부로 읽거나 밖으로 보내지 마세요. 특히 다른 플러그인의 app\plugindata\<id>\(예: LUMI Chat 의 plugindata\lumi.ai\ — AI 키와 대화 기억)는 사용자만의 것입니다.
  • 예외는 여러분 플러그인 안에서 끝납니다. start()에서 예외가 나면 그 플러그인만 「불러오지 못했어요」가 되고 루미는 계속 뜹니다. 이벤트 함수 안의 예외도 로그에만 남습니다.
  • 화면(Swing)은 EDT에서. 창을 만들거나 고칠 때는 SwingUtilities.invokeLater(() -> …). 이벤트 함수와 타이머 스레드에서 직접 건드리면 가끔 이상하게 그려집니다.
  • 루미 본체 클래스는 가릴 수 없습니다. 루미 jar가 항상 먼저입니다. 같은 이름의 클래스를 내 jar에 넣어도 루미 것이 쓰입니다. 본체를 바꾸고 싶으면 ctx.patch(클래스이름, ClassFileTransformer)로 실행 중에 바이트코드를 고칠 수 있습니다(ASM은 루미의 lib\에 있고, ByteBuddy 같은 다른 라이브러리는 내 jar에 넣어서). 단 스팀 게이트·오프라인 증표·기능 잠금·플러그인 로더·스팀 연동·호감도 저장소·도전과제 클래스는 거부됩니다.
  • 런처가 지키는 파일. mods\로는 루미 본체(jar·jre·lib), 스팀 관련 파일, 사용자 설정·기록 파일을 덮어쓸 수 없습니다. 전체 목록은 mods\Mods Guide.txt. 거부된 파일은 %TEMP%\littlelumi_launch.log에 적힙니다.
  • 켜고 끄기. 사용자는 「모드」 탭에서 모드 폴더마다, 또 플러그인마다 켜고 끌 수 있습니다. 켜는 것도 끄는 것도 다음 실행부터이고(실행 중에는 아무것도 싣거나 내리지 않습니다), 바뀐 줄에는 「다음 실행 시 적용」이 붙습니다. 루미를 --no-plugins로 실행하면 아무것도 안 실립니다(스팀 실행 옵션에 적으면 됩니다).
  • 순서는 「아래가 이긴다」. 「모드」 탭은 창작마당에서 받은 것과 내 모드를 한 목록으로 보여 주고, 줄 왼쪽 손잡이(≡)를 끌거나 ▲▼ 단추로 순서를 바꿉니다(「자세히」를 누르면 경로·플러그인 상태·단추가 펼쳐집니다). 위에서 아래로 차례로 적용되니 아래에 있는 모드가 같은 파일·같은 플러그인 id를 덮어씁니다. 겹치는 것이 없는 모드에는 「순서가 영향을 주지 않아요」라고 적힙니다. 순서는 mods\order.txt에 저장됩니다.
  • 업데이트했으면 사용자에게 보입니다. jar가 바뀌면 탭에 「지난 실행 이후 바뀜」이 붙습니다. version을 올려 주세요.

나눠 주기

zip으로

의존 라이브러리가 있으면 jar 안에 합치지 않고 plugins\lib\에 따로 넣어도 됩니다. 루미가 그 폴더의 jar도 클래스패스에 올립니다.

mods\hello\ 폴더를 통째로 zip으로 묶어 주세요. 받는 사람은 자기 mods\에 풀고 루미를 실행한 뒤 설정 > 모드에서 권한 안내를 확인하고 「활성화」를 선택합니다. 앱을 완전히 종료하고 다시 켜야 코드와 데이터가 적용됩니다. 안내문 한 장(readme.txt)을 모드 폴더에 같이 넣어도 됩니다. mods\ 바로 아래의 낱개 파일은 무시되니 지저분해지지 않습니다.

스팀 창작마당으로

창작마당 항목에 plugins\ 폴더가 있으면 루미가 「플러그인 항목」으로 알아보고, 모드 목록에 등록합니다. 파일은 Steam 다운로드 원본에서 읽습니다. 구독한 코드 모드는 기본적으로 꺼져 있습니다. 설정의 모드 체크박스를 켜고 위험 안내에 동의하면, 코드와 데이터가 다음 앱 실행부터 적용됩니다. JAR 또는 의존 라이브러리가 바뀌면 다시 동의해야 합니다. 항목 폴더는 모드 폴더와 같은 모양이면 됩니다.

hello-workshop\ ├─ plugins\mynick.hello.jar ├─ plugins\plugin.json ← 있으면 좋습니다(항목 페이지 참고용). jar 안의 것이 진짜 ├─ plugins\lib\*.jar ← 의존 라이브러리 └─ img\…, conf\… ← 데이터를 같이 실어도 됩니다

모드에는 사운드·이미지·텍스트·글꼴·메타데이터와 사용자 정의 데이터 파일을 동봉할 수 있습니다. 앱은 WAV·OGG(Vorbis)·MP3·FLAC·AIFF·AU 사운드와 PNG·JPEG·GIF·BMP·TIFF·WBMP 이미지를 읽습니다. WebP·AVIF, AAC·Opus 등 그 밖의 데이터도 보존하지만 사용하려면 해당 모드의 디코더가 필요합니다. 확장자 없는 README·LICENSE도 사용할 수 있습니다. 지원하지 않는 실행 파일·스크립트는 차단합니다. JAR·행동 XML·지원 스크립트와 native/ 또는 audio-native/ 아래의 Windows x64 DLL을 포함한 모드는 출처와 실행 파일 목록·내용에 대한 동의가 필요합니다. plugins/runtime/에는 보조 실행 도구와 동반 파일을 넣을 수 있으며, 이 디렉터리 전체를 실행 코드로 취급합니다. EXE·DLL·PYD는 Windows x64 형식을 지원합니다. Windows 실행 코드는 내용 복사 없이 잠근 하드링크 경로를 사용하며, 일반 데이터는 원본에서 직접 읽고 실제 사용 시 검증합니다. 이미지·음성 등 일반 데이터만 변경하면 재동의를 요구하지 않습니다. 모드 파일은 앱 종료 후 변경하세요. 실행 중 음원이 없어지거나 손상되면 해당 재생을 건너뜁니다. 비활성·미승인 패키지는 데이터까지 적용하지 않습니다. 정보 XML·정적 SVG는 외부 참조와 실행 요소를 검사합니다.

가장 쉬운 길은 루미 안에서 올리는 것입니다. 트레이 → 설정 → 「모드」 탭에서 내 모드 줄의 「창작마당에 올리기」를 누르면 그 폴더가 그대로 항목이 됩니다(제목·설명·미리보기 그림만 적습니다). 한 번 올리면 같은 줄의 단추가 「창작마당 업데이트」로 바뀌어 다음부터는 그것으로 갱신합니다(항목 번호는 workshop-upload.txt에 적힙니다). 스팀이 켜져 있어야 합니다.

올리기 전에 tools\pack_workshop.py로 검사하세요. 이 도구는 패키지 경로·실행 파일 위치·Windows PE 헤더·크기와 파일 수를 확인합니다. 지원하지 않는 파일이 있으면 실패하며 일부 파일을 버린 패키지는 만들지 않습니다. 원본 전체를 보존한 업로드 폴더와 item.vdf 밑틀을 만듭니다. 이미지·음원·XML 등 내용의 최종 검사와 실행 동의는 앱에서 추가로 확인합니다. --strict는 이전 명령과의 호환용이며 현재는 항상 파일 누락을 거부합니다.

python tools\pack_workshop.py C:\LumiPlugins\hello-workshop --check
python tools\pack_workshop.py C:\LumiPlugins\hello-workshop

--check 는 검사만 하고 아무것도 만들지 않습니다. 그냥 돌리면 걸러진 폴더 dist\workshop\<이름>\ 와 그 옆의 <이름>-item.vdf 가 생깁니다(--out 으로 자리를 바꿀 수 있습니다).

스팀 없이 명령줄로 올리고 싶으면 SteamCMD도 됩니다. 처음 한 번만 조금 번거롭습니다.

  1. SteamCMD를 받아 아무 폴더에 풉니다.
  2. 스팀 계정으로 창작마당 약관에 한 번 동의합니다.
  3. item.vdf를 만듭니다. 위 pack_workshop.py 를 돌렸다면 <이름>-item.vdf 가 이미 만들어져 있으니 title 과 previewfile 만 채우면 됩니다. 손으로 쓸 때는 아래를 베끼세요. contentfolder와 previewfile은 절대 경로, 미리보기는 512×512 PNG. 처음 올릴 때는 publishedfileid를 0으로.
item.vdf"workshopitem"
{
    "appid"            "5075020"
    "publishedfileid"  "0"
    "contentfolder"    "C:\\LumiPlugins\\hello-workshop"
    "previewfile"      "C:\\LumiPlugins\\hello-preview.png"
    "visibility"       "0"
    "title"            "Hello LUMI 플러그인"
    "description"      "루미가 뜨면 인사해요. 플러그인 항목 — 구독하면 다음 실행부터 실려요."
    "changenote"       "첫 업로드"
}
steamcmd +login 내스팀아이디 +workshop_build_item C:\LumiPlugins\item.vdf +quit

올라가면 SteamCMD가 항목 번호를 알려 줍니다. 그 번호를 publishedfileid에 적어 두면 다음부터는 같은 명령이 그 항목을 갱신합니다. 설명은 항목 페이지에서 편집해도 됩니다. 항목 설명에 「플러그인이 하는 일」과 「인터넷을 쓰는지」를 꼭 적어 주세요. 사용자가 그것을 보고 고릅니다.

모드 SDK

첫 플러그인에서 쓴 모드 SDK 는 zip 하나입니다. 이런 것이 들어 있습니다.

LittleLUMI-ModSDK-<앱 버전>-<빌드>\ ├─ lib\ ← 컴파일 전용 jar (루미 본체 + 라이브러리). 스팀 없이는 실행되지 않습니다 ├─ tools\build_plugin.py ← 플러그인 굽기 (첫 플러그인에서 쓴 그 도구) ├─ tools\run_tests.py ← 내 플러그인의 test\*.java 를 굽고 돌리기 (PluginTestKit) ├─ tools\pack_workshop.py ← 창작마당에 올리기 전 검사 + 원본 전체를 보존한 폴더와 item.vdf 밑틀 ├─ docs\API.md ← 공개 API 참조 (API.md 한국어 · API.en.md 영어) — 안정/「실험」 표시와 「호환 정책」. 필요한 것. JDK 25 와 파이썬 3(준비물). 도구는 --javac → JAVAC → JAVA_HOME → PATH 순으로 javac를 찾습니다(build_plugin.py·run_tests.py 둘 다).

어디서 받나요. Little LUMI SDK 다운로드에서 사용하는 루미와 같은 버전의 릴리스를 고르세요. Assets에서 LittleLUMI-ModSDK-로 시작하는 ZIP을 받으면 됩니다. 압축을 푼 뒤 lib\Shimeji-ee.jar와 sdk.json이 있는지 확인하세요. SDK 와 본체는 같은 버전 번호를 씁니다(현재 SDK/앱 1.5.1, API 1). 문서나 예제의 개정 내용은 배포 안내에서 확인하세요. 앱 버전마다 바뀐 것은 docs\CHANGELOG.md에 있습니다.

호환 정책. API 표의 항목은 안정과 실험 둘로 나뉩니다. 표시가 없는 항목은 안정이고, 같은 api_version 안에서는 더해지기만 합니다 — 없어지거나 모양이 바뀌지 않습니다. 「실험」 칩이 붙은 항목은 아직 바뀌거나 없어질 수 있고, 그럴 때는 docs\CHANGELOG.md에 적힙니다. api_version이 오르면 직전 버전을 위해 만든 플러그인은 한 버전 더 실립니다. 나중 버전에서 더해진 문은 같은 api_version이라도 옛 앱에는 없으니, 검증한 앱 버전을 plugin.json의 app_version에 적어 두세요. 전문은 docs\API.md 「호환 정책」.

조건 한 줄. SDK 는 루미 플러그인을 만드는 데만 쓰고 다시 배포하지 않기, 만든 모드는 무료로만 공개하기, 루미 캐릭터·그림·대사의 권리는 STUDIO LUMI 에 있음 — 전문은 zip 안 LICENSE-SDK.txt.

끝날 때. stop() 뒤에는 컨텍스트로 등록한 것만 루미가 거둡니다 — 직접 만든 창·작업 스레드·prefs().onChange 리스너는 stop()에서 직접 정리하세요. 해제된 컨텍스트의 ask()는 부른 스레드에서 바로 -2를 돌려주고, 잘못된 every() 인자(null·주기 0 이하)는 그 뒤에도 예외를 던집니다. 자세한 규약은 docs\API.md의 「생명주기」.

판정을 바꾸고 싶다면 훅부터. 이벤트는 「일어난 뒤 알림」이고, 기능 안의 판정(조용히 할지, 어떤 대사를 고를지, 호감도를 얼마나 줄지)은 훅이 먼저 물어봅니다. 훅이 없는 자리만 examples\plugin-transformer처럼 클래스 변환기로 고치세요 — 그것은 마지막 수단입니다. 변환기가 건드리는 본체 클래스의 모양은 호환 정책 밖이라, 앱이 업데이트되어 그 메서드가 바뀌면 깨집니다. 여러 플러그인은 함께 삽니다 — 클래스패스가 모드 목록의 역순으로 붙어 아래 모드의 변환기가 먼저 등록되지만, ServiceLoader 의 순서는 약속이 아니니 순서에 기대지 마세요.

훅으로 판정 바꾸기

훅은 루미가 정하기 전에 플러그인에게 묻는 자리입니다. 이벤트(ctx.on)가 「방금 이런 일이 있었어요」라면, 훅(ctx.hook)은 「이렇게 하려는데 괜찮아요?」입니다. 핸들러는 지금까지의 값 current를 받아 새 값을 돌려주거나, 의견이 없으면 null을 돌려줍니다.

// 회의 앱이 앞에 있으면 무조건 조용히 (null = 의견 없음, 앱 판정 그대로)
ctx.hook("focus.quiet", (hook, current, c) -> meetingApp.isForeground() ? Boolean.TRUE : null);
// 밤 10시 이후엔 혼잣말 간격을 두 배로
ctx.hook("selftalk.interval", (hook, current, c) -> LocalTime.now().getHour() >= 22 ? ((Long) current) * 2 : null);
// 내 이미지셋엔 HappyHop 이 없으니 내 춤으로 바꿔치기
ctx.hook("behavior.force", (hook, current, c) -> "HappyHop".equals(current) && "Neko".equals(c.get("imageSet")) ? "NekoDance" : null);

규칙 다섯. ① 핸들러는 루미가 부른 그 스레드에서 바로 돕니다 — 값싸게, 절대 기다리지 마세요(20ms 넘기면 경고). ② 여러 플러그인이 같은 훅에 답하면 모드 목록 순서로 위에서 아래로 불리고 아래가 이깁니다(앞선 답은 current로 옵니다). ③ 예외를 던져도 앱은 안 죽습니다 — 그 핸들러만 건너뛰고 한 번만 로그에 남습니다. 형이 틀린 값도 무시됩니다. ④ 사용자가 건 약속(알람, 직접 누른 부탁하기, say.txt)은 플러그인이 훅으로는 막을 수 없습니다 — 그런 자리에는 훅이 없거나 「미루기」만 있습니다. 루미가 스스로 고르는 것(혼잣말·인사)은 ""로 건너뛸 수 있습니다. ⑤ plugin.json에 "hooks": ["focus.quiet", …]를 적어 두면, 앱에 없는 훅 이름은 로그와 모드 탭 줄에 「이 앱에 없는 훅 N」으로 알려 줍니다(실행은 막지 않습니다).

훅 15개. focus.quiet(조용히 할까) · focus.screen_busy(화면이 바쁜가) · text.localized(번들 글자 전부) · sound.effect(효과음 경로, ""=무음) · behavior.force(감독자가 시키는 행동 이름) · bubble.duration(말풍선 수명) · selftalk.line(혼잣말 대사) · selftalk.interval(간격) · speech.greeting(클릭·수다 인사) · affection.award(호감도 적립) · affection.tier(단계) · place.allowed(옮겨 놓을 자리) · bongo.key_frame(봉고 모드의 키 그림 자리) · bongo.key_input(직접 입력 프레임 공급 — 봉고가 보이는 동안 40 ms마다 묻습니다) · bubble.text(말풍선 글자 직전 — 바꾸기만, 빈 답은 원문). 자리·인자·기본값·주의는 모드 SDK 의 docs\API.md §5 표에, 훅마다 루미가 묻는 자리와 ctx 키는 docs\CATALOG.md §3 에 있습니다.

데이터 모드는 조각으로

행동 하나, 대사 몇 줄, 문구 몇 개를 더하는 모드라면 behaviors.xml이나 language_ko.properties를 통째로 넣지 마세요. 통째 파일은 다른 모드와 겹치면 하나만 살고, 루미가 업데이트되어 그 파일이 바뀌어도 모드 사본이 옛 파일로 되돌립니다. 대신 조각을 두세요 — 파일 이름 뒤에 .d가 붙은 폴더에 「더할 것」만 넣으면 루미가 실행할 때 원본 위에 합칩니다.

mods\my-dance\ ├─ mod.json ← {"name":"My Dance","version":"1.0.0","app_version":"1.5.1"} — 모드 탭에 v1.0.0 칩 ├─ img\Lumi\conf\behaviors.d\dance.xml ← 루미에게 행동 하나 더하기 (아래 예) ├─ img\Lumi\conf\actions.d\dance.xml ← 그 행동이 쓰는 동작 ├─ conf\language.d\my-dance_ko.properties ← 문구 덮기·더하기 (ko 에만). my-dance.properties 는 모든 언어의 빠진 키만 └─ conf\self_talk.d\my-dance_ko.txt ← 혼잣말 몇 줄 (원본 뒤에 붙습니다)
img\Lumi\conf\behaviors.d\dance.xml<?xml version="1.0" encoding="UTF-8" ?>
<Mascot xmlns="http://www.group-finity.com/Mascot">
  <BehaviorList>
    <Behavior Name="MyDance" Frequency="10">
      <NextBehaviorList Add="false"><BehaviorReference Name="Fall" Frequency="1"/></NextBehaviorList>
    </Behavior>
  </BehaviorList>
</Mascot>

규칙. ① 조각은 원본과 같은 모양의 온전한 XML입니다(뿌리 <Mascot>). 목록 안의 것이 원본에 덧붙고, 같은 Name이 이미 있으면 그 자리에서 바뀝니다. ② 여러 모드가 같은 이름을 바꾸면 모드 목록에서 아래가 이깁니다. ③ 대사 조각은 원본 뒤에 붙어서 보이스팩 번호가 안 밀립니다. ④ 문구 조각은 파일 이름 끝의 언어(_ko·_ja·_zh·_zh_TW·_en)에만 적용됩니다. ⑤ 깨진 조각은 그 파일만 건너뛰고 로그에 한 줄 남습니다. 합친 결과가 엔진 검사에 걸리면 루미는 조각 없이 다시 읽습니다 — 캐릭터가 사라지는 일은 없습니다. ⑥ 조각은 모드 탭 「겹침」에 안 셉니다.

버전 표기. 모드 폴더 맨 위의 mod.json(플러그인이면 plugin.json)에 version과 app_version을 적어 두면 모드 탭 줄에 v1.0.0 칩이 붙고, 지금 루미 버전과 다르면 「〈그 버전〉용」 칩으로 알려 줍니다(막지는 않습니다).

목록 아이콘. 모드 폴더 맨 위에 icon.png를 두면 모드 탭 줄의 제목 앞에 작은 아이콘으로 보입니다(정사각이 가장 잘 보이고, 비율은 지켜 줄여 넣습니다). 없으면 캐릭터가 든 모드는 그 캐릭터의 첫 그림을, 그 밖에는 모드 종류를 그린 기본 아이콘을 씁니다. PNG만 읽으며 8 MiB·한 변 8192px·총 4천만 화소를 넘거나 깨진 파일은 건너뜁니다. 다음으로 캐릭터 그림을 확인하고, 읽을 그림이 없으면 기본 아이콘을 표시합니다. 맨 위의 파일이라 루미 폴더에 덮어쓰이지 않고 「겹침」에도 안 셉니다.

용어 사전

JDK / JRE
Java 개발 도구 / 실행 도구. 굽는 데는 JDK, 루미가 도는 데는 JRE(루미에 내장).
jar
Java 프로그램을 담는 zip 파일. 플러그인 하나 = jar 하나.
클래스패스 (-cp)
컴파일러에게 「이 코드가 부르는 다른 코드는 여기 있다」고 알려 주는 목록. 루미 jar와 lib\*를 적습니다.
패키지
클래스의 성(姓). package hello;라고 적은 파일은 src\hello\ 폴더에 있어야 합니다.
ServiceLoader / META-INF/services
「이 jar에 이런 진입점이 있다」를 파일 이름으로 알리는 Java 표준 방식. 진입점 파일이 그것입니다.
EDT
Swing이 화면을 그리는 하나뿐인 스레드. 창을 건드리는 코드는 여기서 돌아야 합니다.
이미지셋
캐릭터 한 명. app\img\ 아래 폴더 이름이 곧 이름입니다(루미는 Lumi).
오버레이
루미가 시작할 때 mods\의 파일을 app\ 위에 덮어 쓰는 것. 모드가 설치되는 원리.

이 가이드는 플러그인 API 버전 1을 기준으로 합니다. API 버전이 오르면 이 페이지의 표기도 함께 바뀝니다.
